# 試しにプログラムを書いて見つかった穴

## 2 回目（スレッドのあと。2026-10-23）

`examples/parallel_words.jw`（スレッドで単語を数える）、`examples/calc.jw`（電卓。再帰する enum と `?`）、
`examples/shop.jw`（在庫と注文。構造体の辞書・interface のリスト・並べ替え）を書いた。3 本とも、インタプリタ・IR・実行ファイルで同じ結果になる。

### 結論

一番大きい穴は **「クロージャが外の変数をムーブしてしまう」** こと。`sort_by` に辞書を見る比べ方を渡しただけで、辞書が使えなくなる。
次に、**リストの要素を取り出しながら回せない**（`for` はいつも借りる）ことと、**match で `Some(Op(op))` のように重ねて書けない** こと。

### 書けなかった・書きにくかったもの

| # | 困ったこと | 出会った場所 | 今の回避策 | 重さ |
|---|---|---|---|---|
| 1 | **（解決）** クロージャが外の辞書・構造体をムーブする（`keys.sort_by((a, b) -> total[a] > total[b])` のあと `total` が使えない） | parallel_words・shop | 先に `let t = ref total;` を取り、`t` を取り込む | 大 |
| 2 | **（解決）** リストの要素を取り出しながら回せない（`for p in parts` の p は `ref`。スレッドへ渡せない） | parallel_words・shop | `loop { match parts.pop() { ... } }`（逆順になる） | 中 |
| 3 | **（解決）** match の形を重ねられない（`case Some(Op(op))`） | calc | 「終わり」を表す種類を enum に足すか、match を 2 段にする | 中 |
| 4 | **（解決）** リストに `filter` / `map` がない | shop | for で新しいリストに push | 小 |
| 5 | **（解決: `ok_or(o, e)?`）** Option を Result の関数で `?` できない（`s.to_int()?`）。Option → Result に変える関数がない | calc | match で受けて `return Err(...)` | 小 |
| 6 | **（解決: `task<()>`）** 値を返さない task の型が書けない（`task<???>[]`） | parallel_words | クロージャから `0` を返して `task<i64>` にする | 小 |
| 7 | **（解決: `"""..."""`）** 文字列を途中で改行できない（複数行の文字列がない） | parallel_words | `\n` を書く | 小 |
| 8 | 文字型がない（`"0123456789".contains(c)` で数字かを調べる） | calc | 1 文字の str で比べる | 小（未実装の一覧にある） |
| — | 辞書の要素を `ref mut m[k]` で借りられない | shop | `m[k].f -= 1` と毎回キーで引く | 決めたとおり（中の場所が変わるため） |

### 見つかったバグ（直した）

- `?` で返す Err / None の型が関数の戻り値の型と違うとき（`Result<i64[], str>` を `Result<i64, str>` の関数で `?`）:
  インタプリタは「ムーブする値」の印のまま返していたので、正しいプログラムが「ムーブ済み」のエラーで止まった。
  IR はそのまま返していたので、実行ファイルを作れなかった。→ 中身でコピーかを決め直す・IR は Err / None を作り直す。
- `(own Shape)[]` のような interface の own のリストを `for` で回すと、実行ファイルを作れなかった。→ llvm.rs の `coerce` に足した。

### 進める順番の案

1. **#1 クロージャの取り込み**。→ 引数にその場で書いたクロージャは外の変数を借りるようにした（オーナーがカードで A を選択）。
2. #2 取り出しながら回す `for`。→ `for x in a.drain()` で要素を値として受け取る（オーナーがカードで A を選択）。
3. #3 match の重ねた形。→ 実装済み（`calc.jw` も書き直した）。
4. #4〜#7 の小さいもの（`filter` / `map`、`ok_or`、値なしの型名、複数行の文字列）。→ すべて実装済み。

## 1 回目

`examples/bst.jw`（二分探索木）、`examples/words.jw`（単語の数え上げ）、`examples/battle.jw`（interface のリストと構造体の中の ref）を書いて分かったこと。

### 結論

一番大きい穴は **「own でない値を借りられない」** こと。木やリストを関数に渡すたびに `own` で包む必要があり、コードが重くなる。
次に、文字列の操作・辞書・リストの remove がないため、ふつうのプログラムが書きにくい。
ライフタイムを書かずに済む点（構造体に ref を入れる、ref を入れ直す）は、問題なく書けた。

### 書けなかった・書きにくかったもの

| # | 困ったこと | 出会った場所 | 今の回避策 | 重さ |
|---|---|---|---|---|
| 1 | **（解決）** own でない値（構造体のフィールド・ローカルのリスト）を `ref` で借りられない | bst: `match ref mut root`、`ref mut keys` | フィールドを `own Option<own Node>`、ローカルを `own i64[]` にする | 大 |
| 2 | **（解決）** 構造体を要素に持つリストを `for x in a` で回せない | words: `for c in counts` | `for i in range(a.len())` と添字 | 中 |
| 3 | **（解決）** リストの `remove` / `insert` がない | battle: 倒した敵を消す | 最後の要素だけ `pop` | 中 |
| 4 | **（解決）** 辞書（ハッシュマップ）がない | words | リストを先頭から探す | 中 |
| 5 | **（解決）** 文字列のメソッドがない（`len`・1 文字ずつ・分割・数への変換） | words: 文章を単語に分けられない | 単語のリストを直接書く | 中 |
| 6 | **（解決）** 埋め込み `"{keys}"` で own を書くと `<own #1>` と出る | bst | `"{*keys}"` と書く | 小 |
| 7 | **（解決）** 入力がない（標準入力・ファイル・引数） | 全部 | データをプログラムに直接書く | 中（ベンチマークには不要） |

### 性能について気づいたこと（3・4 の段階に効く）

- 静的解析で消せた世代チェックは、木で 1 / 20 か所、シミュレーションで 0 / 12 か所。`ref` を引数で受け取る関数や `loop` の中で `ref` を入れ直すコードでは、ほとんど消せない。
- 「Go より速い」には、IR の段階で消せる検査を増やす工夫か、検査そのものを安くする工夫（ランタイムの設計）が要る。

### 問題なく書けたもの

- `Option<own Node>` での再帰的な構造体、`match ref mut` で中を書き換える再帰
- 構造体のフィールドに `Option<ref mut Unit>`（interface への ref）を入れる
- `(own Unit)[]` に違う構造体を混ぜて入れ、`ref mut enemies[i]` で借りる
- 要素を `pop` したあとで、その要素を指す ref を使うと、ダングリングとして正しく止まる
- `out[i].n += 1` のように、リストの中の構造体のフィールドを書き換える

### 1（穴埋め）で進める順番の案

1. **own でない値を借りる**（#1）。言語の書き心地を一番大きく変え、IR の設計にも関わるので最初にする。→ 実装済み。あわせて `ref` の引数は自動で借りるようにした。
2. シャドーイングの禁止（予定どおり）。→ 実装済み。
3. リストの `remove` / `insert`、構造体の要素の `for`（#2, #3）。→ 実装済み。
4. 文字列のメソッド（#5）と、埋め込みでの own の表示（#6）。→ 実装済み。
5. 辞書（#4）。→ 組み込みの型 `V[K]` として実装済み（キーは整数・str・bool）。
6. 入力・enum のメソッド・interface から構造体を取り出す・小数・モジュールは、そのあと。
   → 入力・小数は実装済み。クロージャ（関数を値として渡す）と並べ替え `sort` / `sort_by` も実装済み。
