# 型安全性の核（Lean）

`formal/JabberwockFormal/CoreTypeSafety.lean` で、jabberwock の小さな核の言語について
「型が付くプログラムは行き詰まらず、出てくる値は型どおり」を証明する。少しずつ広げるための最初の一歩。

## 範囲

- 型: `int`（i64）と `bool`
- 式: 整数・真偽値の定数、変数（let と関数の引数）、`+` `-` `/`、`<`、`==`（同じ型どうし）、`if`、`let`、
  引数 1 つのトップレベル関数の呼び出し（再帰も可）
- 評価: 燃料（深さ）つきの big-step。結果は `ok v`・`err`（仕様の実行時エラー: i64 のあふれ、0 で割る、
  最小値 / -1）・`fuel`（燃料切れで打ち切り）・`stuck`（行き詰まり）

## 定理

| 定理 | 内容 |
|---|---|
| `eval_safe` | 関数の表の型が合い、環境の値が型どおりなら、型 t の式の評価結果は stuck でなく、値なら型が t（燃料はいくつでも） |
| `never_stuck` | 型が付く式の評価は stuck にならない |
| `closed_value_has_type` | 変数のない式の結果が値なら、その型は式の型 |

## 所有権を足した模型（`CoreOwnership.lean`）

上の核に、整数を 1 つ持つ所有の箱（`own` の値）を足した模型。

- 足した式: `mkBox e`（箱を作る）、`move i`（変数 i の箱を移動。i はそのあと死ぬ）、
  `peek i`（ref で中身を読む。移動しない）、`unbox e`（箱を使い切って中身を取り出す）
- 型の規則は変数の生き死にを追う（`HasTy fs Γ e t Γ'`: 評価したあとの文脈が Γ'）。
  移動した変数を使う式、箱をコピーする式には型が付かない
- 実行時の環境は「値」か「移動済み」の列。移動済みの変数を使う、箱をコピーすると行き詰まり（stuck）

| 定理 | 内容 |
|---|---|
| `eval_safe` | 型が付く式を文脈と合う環境で評価すると stuck でなく、値なら型どおりで、評価後の環境も評価後の文脈と合う |
| `moved_access_stuck` | 移動済みの変数を読む・移動する・覗くと stuck になる（上の定理が意味を持つことの確認） |
| `no_use_after_move` | 型が付く式の評価は stuck にならない。つまり移動済みの変数を使わず、箱をコピーしない |

この模型にない所有権の要素: 書き込みできる `ref mut`、借用の期間（ref を持っている間の移動の禁止）、
世代つき ref の実行時検査、構造体の中の所有、解放（drop）の時期。

## 借用の期間を足した模型（`CoreBorrow.lean`）

所有の箱に、読み取り専用の ref と借用の期間を足した模型。

- 変数は環境の先頭からの位置で指す。let と borrow は末尾に足し、終わると末尾を外す
- `borrow i body`: 変数 i の箱への ref を新しい変数に入れて body を評価する。body の間 i は凍り、
  移動できない（`peek` はできる）。終わると凍結を解く
- `deref e`: ref の指す変数を読む。指す先が移動済みなら行き詰まり（宙に浮いた ref）
- ref はコピーできるが、let・borrow・関数の外へは持ち出せない（結果の型は ref でない、関数の引数・戻り値も ref でない）

| 定理 | 内容 |
|---|---|
| `eval_safe` | 型が付く式を文脈と合う環境で評価すると stuck でなく、値なら型どおりで、評価後の環境も評価後の文脈と合う |
| `dangling_deref_stuck` | 移動済みの変数を指す ref を読むと stuck になる（上の定理が意味を持つことの確認） |
| `no_dangling` | 型が付く式は、移動済みの変数も宙に浮いた ref も使わない |

この模型にない借用の要素: `ref mut`（書き込み）と「書き込みの ref は 1 つだけ」、ref を関数に渡すこと、
構造体や戻り値に入る ref、世代つき ref の実行時検査（jabberwock の実物は ref を外へ持ち出せ、世代で検査する）。

## 書き込みの借用を足した模型（`CoreMutBorrow.lean`）

上の模型に、書き込みの借用（ref mut）を足した模型。

- `borrowMut i body`: 変数 i の箱を body の間だけ貸し出す。実行時は箱を ref mut の変数へ移し、i は空にする。
  終わると中身を i に書き戻す。型の上では、その間 i は「貸し出し中」で、読む・動かす・ref を作る・もう一度貸すことはできない
- `getM j` / `setM j e`: ref mut の変数を通して読む・書く（整数を書き、箱のまま）
- ref mut の変数はコピーも移動もできない（ただ 1 つ）

| 定理 | 内容 |
|---|---|
| `eval_safe` | 型が付く式を文脈と合う環境で評価すると stuck でなく、値なら型どおりで、評価後の環境も評価後の文脈と合う |
| `lent_owner_stuck` | 貸し出し中の持ち主（実行時は空）を読む・動かす・覗くと stuck になる（上の定理が意味を持つことの確認） |
| `no_conflict` | 型が付く式は、移動済みの変数・宙に浮いた ref・貸し出し中の持ち主を使わない |

この模型にない要素: ref mut を関数に渡すこと・外へ持ち出すこと、読み取りの ref と ref mut を同時に持つ他の形、
構造体の一部だけを借りること、世代つき ref の実行時検査。

## 世代つき ref の実行時検査の模型（`CoreGenRef.lean`）

借用の期間に縛られない ref を、読むときの世代の検査で守る模型。上の 3 つとは別に、小さな核から作った。

- 変数の値は区画に置く。区画は世代と中身（持ち主の変数と値）を持ち、中身がなければ空き
- `letE x body`: 割り当ての方針が選んだ空き区画（なければ末尾に新しい区画）に x を置く。body が終わると区画を空け、世代を 1 進める。
  空いた区画は、あとで別の型の値に使い回されうる
- `addr i`: 変数 i の区画の番号と今の世代を ref として返す。ref は let の外へ持ち出してよい
- `deref e`: ref の世代と区画の世代が同じときだけ読む。違えば実行時の誤り（`err`）で止まる
- 割り当ての方針は何でもよい。条件は「空きで、世代が上限未満の区画だけを選ぶ」こと（上限に達した区画は退役して使い回さない）

| 定理 | 内容 |
|---|---|
| `eval_safe` | 型が付く式を、文脈と合う環境・ヒープで、条件を満たすどの方針で評価しても stuck でなく、値なら型どおりで、評価後のヒープも文脈と合う |
| `no_stuck` | 型が付く式は、解放済みの区画も、使い回された区画の別の型の中身も読まない |
| `stale_ref_err` | 世代が合わない ref を読むと、必ず実行時の誤りで止まる |
| `pick_none_ok` | いつも新しい区画を足す方針は条件を満たす（前提が空でないことの確認） |
| `escaped_ref_err` / `reused_ref_err` | 外へ持ち出した ref を読む例、区画が使い回された後に古い ref を読む例が、どちらも `err` で止まる（計算で確認） |

この模型の世代は `Nat` で桁あふれしない。有限の上限は `CoreGenRefBound.lean` でつないだ:

| 定理 | 内容 |
|---|---|
| `eval_bounded` | 上限を守る方針なら、評価の後もどの区画の世代も上限以下、生きた区画と ref の世代は上限未満 |
| `result_ref_lt` | 評価の結果の ref は、上限の世代（退役の印 `GEN_RETIRED`）を持たない |
| `retired_stays_vacant` | 世代が上限に達した区画は、評価の後も上限のまま空きで、使い回されない |

実行時の世代の語（62 ビットの数え・62 番のビットの印・全 1 の退役）へは `CoreGenRefWord.lean` でつないだ。上限を 2^62 に置く:

| 定理 | 内容 |
|---|---|
| `result_word_not_retired` | 型が付く式の結果の ref の語は、退役の語（`GEN_RETIRED`）にならない |
| `gate_matches` | 模型の読むときの検査（世代が等しいか）と、実行時の語の検査（退役でなく語が等しい）は同じ答え |
| `retired_rejects` | 退役した区画の語は、どの保存された語も通さない |

印のビットは区画ごとに変わらないものとして扱う。C のポインタの寿命・原子的な順序・割り当て器のリストの形は扱わない。
ほかにこの模型にない要素: 箱の移動・借用の期間（上の模型）との組み合わせ、
ref を通した書き込み、関数、構造体の中の ref、検査を消す解析（elision）との組み合わせ。

## 持ち主の箱と世代つき ref を合わせた模型（`CoreGenBox.lean`）

jabberwock の `own` と `ref` の使い方に近い形。箱の中身はヒープの区画に置く。

- `mkBox e`: 空き区画（方針が選ぶ。なければ新しい区画）に値を置き、箱を返す
- `move i`: 箱を動かす。元の変数は死に、中身は空になる
- let の終わりに、変数が生きた箱を持っていれば区画を解放し、世代を 1 進める
- `addr i`: 変数 i の箱の区画への ref（番号と今の世代）。let の外へ持ち出してよい
- `deref e`: 世代が合うときだけ読む。違えば実行時の誤り（`err`）
- `peek i`: 生きた箱の中身を読む
- 箱の中身と ref の指す先は、箱を含まない型に限る
- 区画の「持ち主の記録」は検証のための記録で、評価はこれを読まない

| 定理 | 内容 |
|---|---|
| `eval_safe` | 型が付く式を、文脈と合う環境・ヒープで、条件を満たすどの方針で評価しても stuck でなく、値なら型どおりで、評価後の環境・ヒープも評価後の文脈と合う |
| `no_stuck` | 型が付く式は、移動済みの変数・解放済みの区画・使い回された区画の別の型の中身を使わない |
| `escaped_ref_err` | `deref (let b = box 1 in &b)` は、箱が解放された後の ref を読むので実行時の誤りで止まる（計算で確認） |

この模型にない要素: 箱の中の箱、借用の期間（`CoreBorrow`）や ref mut との組み合わせ、ref を通した書き込み、関数、
有限の世代（箱のない模型では `CoreGenRefBound`・`CoreGenRefWord` でつないだ）。

## 範囲の外（未証明）

- 所有権のうち上の模型にないもの、リスト・構造体・enum・match、文と代入、ループ、標準ライブラリ、資源、スレッド
- jwc・Rust 版の型検査器がこの型規則と同じであること、IR・LLVM・jw_rt.c との対応（意味保存）
- 燃料が尽きない（止まる）こと。止まらない計算は `fuel` として安全側に数える

この定理は模型についての証明で、実装の型検査や生成したコードについての証明ではない。
