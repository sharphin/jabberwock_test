## 到達目標と責任範囲

オーナーが示した保証範囲を、形式検証の到達目標として採用する。
下表の「保証対象」は目指す責任範囲であり、現在の実装で証明済みという表示ではない。

| 領域 | Jabberwockの責任 |
|---|---|
| コンパイラの意味保存 | 保証対象 |
| メモリ安全性 | 保証対象 |
| 型安全性 | 保証対象 |
| 所有権・参照の整合性 | 保証対象 |
| 実行時チェックの正しさ | 保証対象 |

例えば、プログラマーが目的に合わない計算式を書いても、その式を言語仕様どおりに実行するコードへ変換する責任はコンパイラが持つ。
プログラムが業務上正しいことと、コンパイラがそのプログラムを正しく実行することを分けて扱う。

保証の内容と完了条件は、次のように具体化する。

| 保証対象 | 証明・検証する内容 | 現在の形式証明の到達点 |
|---|---|---|
| 意味保存 | 仕様上の評価からIR、最適化、Rust版/jwc版のLLVM生成、最終実行まで、許される観測結果を保つ | 未証明 |
| メモリ安全性 | 不正な領域へのアクセス、解放済み領域の利用、境界外アクセスを防ぎ、metadataの検査自体も安全に行う | 世代・退役の抽象モデルのみ部分的に証明 |
| 型安全性 | 型付けした評価状態が遷移で型の整合性を保ち、値・規定のエラー・次の遷移を定義できる | 言語全体の型体系・評価状態は未機械化 |
| 所有権・参照 | 所有者の一意性、所有責任の移動と回収、借用・無効化、送信時の整合性を保つ | 抽象的な所有位置間のムーブと参照の非復活を証明 |
| 実行時チェック | 有効性と権限の条件に一致して許可/拒否し、検査前に不正アクセスを行わない。検査省略後も意味を保つ | 抽象的な世代・phase・書込み権限の検査のみ証明。実装と検査省略は未証明 |

「観測結果」には戻り値、標準出力/標準エラー、仕様上の診断、外部I/Oの順序と回数、終了と非終了を含める。
並行実行では仕様が許す実行traceとの対応を定め、実行ごとに同じスケジュールになるとは要求しない。
許容する資源エラーやプラットフォーム差も明示するが、不正なコンパイル結果を任意の資源エラーとして正当化しない。
debug比較や最適化を理由に、書込み・送信・DB操作を二重実行しないことも意味保存の対象とする。

型の通るプログラムでも、無効なrefやムーブ済みの値の使用などは仕様で定めた実行時エラーになり得る。
型安全性は全プログラムの正常終了、業務要件の達成、アルゴリズムの停止を保証することではない。
`ref mut` の別名参照を許すことや、世代上限で退役することも含め、実際に採用した言語規則について証明する。

アプリで誰を認証し何を許可するかはプログラマーが定める。
一方、Jabberwock側が提供するTLS証明書検証・SQLパラメータ処理・権限検査などは、ライブラリ自身の契約どおりに実装・検証する責任がある。
アプリのロジックが責任範囲外であることを理由に、コンパイラや提供ライブラリのバグを責任範囲外へ移さない。

形式証明の信頼基盤と実装への接続も明記する。
現在はLean kernel・固定ツールチェーンを信頼し、Rust/C/LLVM、OS、外部ライブラリとの対応は未証明。
最終的な意味保存を主張するには、その接続を証明するか、未証明の依存と仮定を明示して保証の条件を限定する必要がある。
1〜7のテスト成功や22個の部分的な定理だけで、上表の5項目全体を保証済みとは表示しない。

## 形式化する言語の核

最初の対象は、単一スレッドで整数の値を所有し、借り、読み書きし、ムーブして解放する核とする。
以下の記法は説明用の核で、jabberwockの新しい構文ではない。

```text
q ::= ro | rw
τ ::= i64 | own i64 | ref(q, i64)
p ::= x | *x
e ::= n | p | own n | borrow(q, x)
c ::= let x = e | x := e | *x := n | drop x | { c* }
```

実際の言語の型は `ref i64` と `ref mut i64`。`q` は寿命や排他性を表さず、書込みの許可だけを表す。
構造体・enum・配列・リスト・写し・closure・interface・関数・スレッドは核へ順に拡張する。
整数の算術そのものと、数値変換の正しさはこの初版の機械証明対象ではない。

静的な環境を `Γ(x) = (τ, mutable)` と書く。
借用は型と書込みの許可を確認し、所有権を複製しない。

```text
Γ(x) = (own i64, m)
----------------------------------------- Borrow-RO
Γ ⊢ borrow(ro, x) : ref(ro, i64)

Γ(x) = (own i64, true)
----------------------------------------- Borrow-RW
Γ ⊢ borrow(rw, x) : ref(rw, i64)

Γ(r) = (ref(rw, i64), m)    Γ ⊢ n : i64
----------------------------------------- Write-Allowed
Γ ⊢ *r := n : unit
```

同じ対象への複数の `ref mut` を禁止する前提は付けない。
ムーブ済み変数や無効な参照を含むプログラムも、型が通った後に規定の実行時エラーで止まり得る。
型安全性の将来の定理も、この規定エラーを許す形で述べる。
上の規則は核の抜粋で、完全な型体系の定義・健全性の証明ではない。

## 抽象状態

完全な評価器へ拡張するための状態を次のように分ける。

```text
State = (control, environment, owners, heap, references, cleanupStack)
owners : OwnershipPosition -> Option AllocationKey
heap   : AllocationKey -> (epoch, phase, payload)
ref    = (AllocationKey, epoch, path, permission)
phase  = Live | Vacant | Retired
```

`AllocationKey` は参照から区別できる区画の識別子で、単なるOSのファイル番号や再利用可能なアドレスではない。
退役したkeyを再割当てしない。異なるWorld/contextの区別は今後の拡張で明示的に導入する。
`OwnershipPosition` は変数だけでなく、一時値・引数・戻り値・評価途中の値の所有位置も含む。
初版のLeanでは世代を持つ一つの区画と所有位置の写像を独立してモデル化しており、
上記のState全体、payload、path、cleanupStackはまだ定義していない。

所有者の一意性は次の述語で表す。

```text
Unique(O) := forall a b key, O[a] = Some(key) /\ O[b] = Some(key) -> a = b
```

これは「二つの所有者を作らない」性質で、リークがないことや、全ての生きた区画に必ず所有者がいることとは別。
それらには評価途中の一時値、複合値、終了処理を含めた追加の不変条件が必要になる。

## 有限世代と退役の規則

論理世代は自然数 `g` で表し、常に `0 <= g <= G` を満たす。
実装上は64ビットに収まる値を使うが、剰余算術としての周回は認めない。
`G <= 2^64 - 1`。状態bit等を同じwordへ詰める実装では、実際に使用できる上限をそれより小さくしてよい。
`G` はモデルと具体表現の対応で定める定数で、利用者が読み書きする値ではない。
Leanの定理は任意の自然数 `G` について成立し、上限0の場合も含む。

許す遷移は次の表のとおり。payloadはこの表では省略する。

| 操作 | 事前状態 | 事後状態 | 条件 |
|---|---|---|---|
| 状態を変えない操作 | `(g, s)` | `(g, s)` | 任意のphase |
| 再割当て | `(g, Vacant)` | `(g, Live)` | `g <= G` |
| 生存中の参照無効化 | `(g, Live)` | `(g+1, Live)` | `g < G` |
| 解放・変数位置の無効化 | `(g, Live)` | `(g+1, Vacant)` | `g < G` |
| 退役 | `(g, Live)` | `(g, Retired)` | `g <= G` |

`g = G` からの無効化では退役が必須。符号や状態bitとの衝突を避ける保守的な早期退役も許す。
`Retired` から `Live` や `Vacant` へ戻る遷移は存在しない。
世代の加算前に表現可能性を確認し、wrapした値を一時的に公開してから補正してはならない。
退役判定は解放だけでなく、再利用、変数のムーブ、リスト要素の移動、スレッドへの送信にも適用する。
借用印の設定など論理世代を変えない補助操作は、参照の有効性を変えない具体表現として別途対応づける。

### 使用中に上限へ達した場合

解放ならpayloadの所有責任を一度だけ処理し、そのkeyを永久に退役させる。
リスト操作や送信など、payloadの使用を続ける操作では次のどちらかとする。

1. 新しいkeyの区画を確保し、payloadの所有責任をムーブし、所有位置を付け替え、古いkeyを退役させる。
2. 安全に移し替えられない・確保できない場合は規定の資源エラーで停止する。

この移し替えは、もともとその操作が無効化する参照を新しいkeyへ勝手に付け替えない。
通常のownのムーブや要素への代入など、参照を無効化しない操作に退役を理由とした無効化を追加しない。
複合値の子区画の同一性と所有責任は、その操作本来の規則に従って保つ。
移し替えは二重所有・二重解放・一部だけ更新された継続状態を残してはならない。
停止する場合は `_Exit` の既存の解放保証を広げたとは扱わない。

古いrefが読む検査用metadataは、そのrefを使用できる間は読み取り可能なまま保持する。
同じ生アドレスをOSへ返して再取得し、古いrefから新しい世代0のヘッダーが見える実装は不適合。
別の安全な識別表で検査するか、refが残らないことを証明できるまでtombstoneを保持する必要がある。
退役metadataの保持量はlive payloadの数とは別に計測し、項目8の資源枯渇の検討対象へ含める。

## 参照の検査

一つの区画に対する機械化済みの条件は次のとおり。

```text
Valid(r, c) := c.phase = Live /\ r.epoch = c.epoch
Read(r, c) := if Valid(r, c) then Ok else Dangling
Write(r, c) := if r.permission != rw then ReadOnly else Read(r, c)
```

完全なheapでは、これにkeyの所属、pathの型・境界、対象のpayloadの存在を加える。
metadata検査が成功する前にpayloadやpathの先を読まない。
`Retired` は世代の数値が一致しても不正な参照として拒否する。
書込み許可は読み取り専用の参照から昇格させない。`ref mut` にaliasがないとは仮定しない。
そのため、`ref mut` だけを根拠にLLVMの `noalias` を付けることはできない。

## ムーブの核

機械化済みのムーブは、異なる二つの所有位置と空の移動先に対して行う。

```text
O[source] = Some(key)    source != target    O[target] = None
----------------------------------------------------------------- Move
O' = O[source := None, target := Some(key)]
```

keyは変わらず、借りたownの先の参照も、通常のムーブだけでは無効にならない。
一方、元の変数位置そのものを借りた参照の無効化は、別の変数区画への遷移として扱う必要があり、まだ機械化していない。
ソースが空・移動先が使用中・同じ場所の場合は核のcheckedMoveがエラーを返す。
これは言語の自己代入の最終仕様ではなく、評価器が使う内部の「異なる空き所有位置へ移す」操作。
実際の代入は右辺の評価・一時値の保護・旧値の解放を含み、この内部操作へ対応づける。

## 機械検査する定理

| 定理 | 内容 |
|---|---|
| `step_preserves_bound` / `steps_preserve_bound` | 初期状態で上限内なら、許す遷移・有限遷移列の後も上限内 |
| `step_epoch_monotone` / `steps_epoch_monotone` | 論理世代は減少しない |
| `retired_is_absorbing` / `retired_stays_retired` | 退役したkeyは復活しない |
| `invalidation_available` | 上限内のLive状態では、世代を進めるか退役する無効化を選べる |
| `no_resurrection` | 有効だった参照を無効化した後、任意の許された有限継続でもその参照は有効にならない |
| `checked_read_iff` / `writable_access_iff` | 読取り・書込みの検査成功が有効性と一致する。書込みはrwを前提とする |
| `retired_read_rejected` / `read_only_write_rejected` | 退役先の参照と読取り専用の書込みを拒否 |
| `move_preserves_unique` / `checked_move_preserves_unique` | 成功したムーブが所有者の一意性を保存 |
| `move_empties_source` / `move_preserves_identity` | 元の所有位置を空にし、移動先は同じkeyを持つ |
| `wrapping_revives_at_two` | 上限を小さくした旧周回モデルでは世代が再び一致する反例 |

`no_resurrection` の無効化条件は `old.g < new.g` または `new.phase = Retired`。
最初から不正に作った将来の世代値が、後で一致することまで禁止する定理ではない。
実際に発行したrefが最初に有効だったことと、全ての継続が定義した遷移に従うことを前提とする。
allocationの成功や無限実行の停止性は証明しない。
旧周回モデルの小さい反例は、現行64ビット実装を実時間で攻撃できたという報告ではない。

検査は `python3 scripts/check_formal.py`。全theoremの公理依存を検査し、証明の穴を認めない。
Leanのkernelと固定されたツールチェーンは信頼の基盤で、数学的に証明済みと仮定する独自の言語公理は追加しない。
