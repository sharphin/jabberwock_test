# 外部の AI（GPT など）に相談するときの指示文

速さと言語機能について、ほかの AI に案を出してもらうときに、そのまま貼って使う文章。
数字は bench/README.md の「結果（2026-10-25）」から。数字が変わったら、ここも直す。

---

## 貼る文章

あなたには、自作のプログラミング言語 **jabberwock** の相談役をお願いします。
リポジトリは https://github.com/sharphin/jabberwock です。実装は別の AI（Claude）が担当します。あなたの役目は、**案を出すことと、案の弱いところを指摘すること**です。
コードを書く場合は、短い例やスケッチにとどめてください。答えは日本語で、平易な言葉でお願いします。

### この言語の狙い

「C++ より安全、Rust より簡単、Go より速い」を狙っています。
そのための道具は 2 つだけです。

- **`own`**: 唯一の持ち主です。読むとムーブし、スコープを抜けると解放します。
- **世代つきの `ref`**: 借りるときに、持ち主の区画の世代を覚えます。使うときに世代を比べるので、解放されたあとに使うと必ず実行時エラーになります。
  ライフタイムの注釈と、借用の検査器はありません。

静的解析で「この ref は生きている」と証明できたところは、世代の検査を消します。証明できないところは、実行時の検査を残します（安全側）。
GC も参照カウントもありません。ただし文字列だけは参照カウントを使います。

### 今の形

- 実装は Rust です（外部クレートは使いません。Rust 1.65 で動くことが条件です）。
  - インタプリタ: 構文木をたどる interp と、IR を実行する exec があります。
  - コンパイラ: IR を LLVM のテキストにして、clang で実行ファイルにします。実行時ライブラリは C で書いています（runtime/jw_rt.c）。
- 自己ホスト版の jwc もあります。jabberwock で書いたコンパイラで、自分自身をコンパイルできます。
- パッケージの道具 alice があります（cargo にあたるものです）。
- 言語の機能は次のとおりです。
  - 型: 整数の型、f64、str、構造体、enum、ジェネリクス、Go 風の interface。
  - 制御: match（形を重ねて書けます）、Result と `?`。
  - 値: クロージャ、リスト、辞書。
  - スレッド: spawn / join / chan。
  - その他: モジュール、ファイルとコマンドの実行。
- 全部の決まりは docs/spec.md にあります。決めた理由は docs/design-decisions.md にあります。

### 守ってほしい前提（ここを崩す案は採れません）

1. **安全は削りません。** 解放後の使用と範囲外の添字は、必ずエラーで止めます。
   検査を消してよいのは、消してよいと証明できたときだけです。「たいてい大丈夫」で消す案は採れません。
2. **ライフタイムの注釈や、Rust のような借用の検査器は入れません。** 書く人の負担を増やさないことが、この言語の売りです。
3. **interp・IR・実行ファイルで、動きを一字一句そろえます。** 出力も、エラーの文も、エラーの位置も同じにします。
   テストはこの 3 つを突き合わせています。なので「実行ファイルだけ動きが変わる」最適化はできません（例外は、外から見えない部分だけです）。
4. 言語の決まりは「前から順に決めるだけ」の型検査で足りる範囲にします。大きな型推論は入れません。
5. シャドーイングは禁止です。改行は文の区切りではありません（`;` で区切ります）。

### まだない機能（決めてあるもの。docs/spec.md の 11 章）

- あふれを確かめる関数（`checked_add` など）
- interface の値から、元の構造体を取り出す（型で分岐する）
- f32 と文字型
- フォルダを分けたモジュール（`use a.b;`）と、メソッドやフィールドごとの `pub`
- 辞書のキーに構造体を使う
- 構造体のフィールドに関数の値を置く・メソッドを値にする
- 標準ライブラリは、まだほとんどありません（組み込み関数とメソッドだけです）

### お願いしたいこと

次の 2 つについて、案を出してください。

**A. 速さ**: 上の表で負けているところを、前提 1〜3 を守ったまま速くする方法です。

- 静的解析で消せる検査を増やす方法も含みます。今の解析は、IR の上の前向きのデータフローです。事実は変数ごとに「own の持ち主」「own 変数 x の先を指す」などを持ちます。
- メモリの置き方を変える方法も含みます。今の区画は 8 バイトの世代の頭を持ち、大きさごとの空きリストで使い回しています。
- スレッドとチャンネルの作り方を変える方法も含みます。

**B. 言語機能**: 「Rust より簡単」を保ったまま、ふつうのプログラムを書きやすくする機能です。

- 上の「まだない機能」の中で、どれを先にやるべきかも聞きたいです。

案ごとに、次の形で答えてください。

1. **案の名前と、一言の説明**
2. **効く理由**: どの処理が、どれくらい速くなる見込みか（または、どんなプログラムが書きやすくなるか）
3. **安全への影響**: 前提 1〜5 のどれかに触れるか。触れるなら、それでも安全だと言える理由
4. **確かめ方**: どのベンチマーク・どんなテストのプログラムで、効いたことを確かめるか
5. **重さ**: 実装の大きさ（小・中・大）と、壊しやすいところ
6. **似た例**: ほかの言語や論文で、似たことをしている例（あれば）

最後に、全部の案に優先順位をつけてください。理由も一行ずつお願いします。
分からないことや、リポジトリを読まないと決められないことは、推測で埋めずに「ここが分からない」と書いてください。
