# Jabberwock 言語安全性契約（v1）

状態: **安全性の設計方針を確定。実装の安全性証明は未完了。**

この文書は、Jabberwock が**言語機能として**保証を目指す性質と、アプリケーション開発者が責任を持つ性質の境界を定める。実装やLeanモデルで未証明の性質を「証明済み」と解釈してはならない。

## 原則

1. 利用者にメモリ安全性を破る `unsafe` 相当の脱出口を提供しない。証明または検査で安全性を確認できず、信頼できる境界契約も存在しない操作は拒否する。
2. 安全性はプログラマの自己申告ではなく、型規則、静的証明、必要な実行時検査、および明示した信頼境界によって担保する。
3. 最適化は安全性を弱めてはならない。実行時検査の省略には、対象アクセスでの有効性を裏付ける証明が必要である。
4. 言語の汎用性・性能は目標だが、安全性の例外をユーザーに公開して達成するものではない。
5. 保証は**対象と前提を伴う**。外部ABI、OS、アロケータ、Cランタイム、コンパイラのバックエンド、ハードウェアなど、信頼境界の内外を明示する。

## 言語としての保証目標（現時点では未達成項目を含む）

- **メモリ安全性:** 不正な参照外し、use-after-free、double-free、範囲外の読み書き、未初期化領域の不正使用を起こさせない。拒否はコンパイルエラーまたは仕様化された実行時エラーとする。
- **所有権・借用・参照:** 一意所有、移動後の旧所有者利用禁止、借用先の無効化、世代付き参照の有効性を守る。
- **型と演算:** 型付けされた操作のメモリ表現との整合性を維持し、整数オーバーフロー・ゼロ除算などは言語仕様で挙動を規定する。未規定の挙動を「安全」と見なさない。
- **並行性:** データ競合を許さないことを目標とするが、実際に保証できる範囲は並行処理機能の仕様・実装・検証後に確定する。
- **コンパイル/実行の全経路:** インタプリタ、Rust製コンパイラ、セルフホスト版、生成コード、ランタイム、最適化を跨いで対象の保証が保持されることを目標とする。
- **外部境界:** FFI、OS・デバイス操作などで検証不能な性質を黙って内部保証へ取り込まない。公開APIを安全にするために必要な隔離・権限・前提は個別仕様で定義する。

上記の保証目標はアプリケーションが終了すること、資源が枯渇しないこと、すべての実行が成功することを意味しない。

## 言語が保証しないもの

- アプリケーションの業務ロジックの正しさ、金銭処理の正当性、意図した結果
- 認証・認可・アクセス制御ポリシーの正しさ
- SQLインジェクション、XSS、SSRFなどの**アプリケーション・プロトコル固有の脆弱性**が生じないこと
- 個人情報・秘密情報の扱いに関するアプリケーション固有の方針の妥当性
- デッドロック不在、サービス可用性、リアルタイム性、サイドチャネル耐性など、別途仕様と証明が必要な性質

標準ライブラリがこれらの対策を支援しても、アプリケーション固有の正しさが自動で保証されるわけではない。

## 証拠の分類

| 分類 | 意味 | 全体の証明と見なすか |
| --- | --- | --- |
| `MODEL_PROVEN` | Leanが抽象モデル内の性質を証明 | いいえ |
| `CONDITIONAL_PROVEN` | 明示された前提の下でLeanが証明 | いいえ |
| `STRUCTURE_MATCHED` | 生産実装のソース形状が期待パターンと一致 | いいえ |
| `REFINEMENT_PROVEN` | 実装と抽象モデルの意味論的な対応を証明 | 当該境界のみ |
| `END_TO_END_PROVEN` | 対象経路と信頼前提を列挙して生成コードまで証明 | 対象性質についてのみ |
| `NOT_PROVEN` | 必要な証拠が不足 | いいえ |

`scripts/formal_tool.py` が `FINAL: NOT_PROVEN` を報告する間、上記の完了は宣言しない。

## 優先する証明順序

1. **安全性仕様と信頼境界:** 言語の操作的意味論、メモリ表現、外部依存の契約を明確化。
2. **メモリモデルと実装の対応:** 所有権移動、解放、世代無効化、読み書きについて、一段階ずつ精密化証明を作る。
3. **検査省略の健全性:** `FactSoundAtAccess` を実際のCFGデータフロー、アクセスの妥当性へ結び付ける。
4. **CFG解析の停止性:** `changeCount ≤ n` と再登録の有限性を証明し、解析の完了を裏付ける。
5. **エンドツーエンド:** ソースから出力コードまでの意味保存と、列挙された信頼境界を接続する。

**判定ルール:** メモリ安全性とコンパイラ精密化は別々に報告し、言語全体の安全性およびアプリケーションの安全性を混同しない。
