# IR（中間表現）の設計案

jabberwock のソースと LLVM の間に置く「中間の命令列」の設計。木をたどるインタプリタ（今の `interp.rs`）では暗黙だった
**ムーブ・解放・世代チェック** を、1 つずつ命令として書き出すのがねらい。

## 結論

- IR は **関数ごとの「基本ブロック＋命令」**（Rust の MIR に近い形）。`if` / `while` / `match` / `?` / `break` はすべて飛び先のある命令になる。
- **型はすべて具体的**。ジェネリクスは使われる型ごとに関数を作り分ける（単相化）。interface は関数の表（vtable）で呼ぶ。
- **解放と検査が見える**: `drop`（own を解放）、`dead`（変数の寿命の終わり＝世代を進める）、`check`（ref の世代チェック）が命令として並ぶ。
  静的解析で消せた `check` は IR に出さない。
- 正しさは **今のインタプリタと突き合わせて** 確かめる。IR を実行する小さなインタプリタを作り、今あるテストを全部両方で走らせて出力をそろえる。
  LLVM へ進むのは、それが全部そろってから。
- 決めごと（2026-10-23 オーナー確認）: スレッドは LLVM のあと。実行時エラーは通常の作り方では「借りた → 解放 → 使った」の時系列、
  `--release` では使った位置だけ。オーナーの環境は Windows（clang はその段階で入れる。開発中はこちらの Linux で確かめる）。

## 全体の流れ

| 段 | 今 | IR 導入後 |
|---|---|---|
| 字句・構文・モジュール | `lexer` / `parser` / `modules` | そのまま |
| 型検査 | `types.rs`（調べるだけ） | **式ごとの型と、呼び出しごとの型の引数を記録する** |
| 検査を消す解析 | `analyze.rs`（構文木の上） | はじめは結果をそのまま使う。のちに IR の上へ移す（制御の流れが見えるので書きやすい） |
| 実行 | `interp.rs` | 残す（正しさの基準）。IR インタプリタと突き合わせる |
| コード生成 | なし | IR → LLVM のテキスト（.ll）→ clang |

## IR の形

```
fn sum(ref i64[] v) -> i64
  locals: _0: i64 (戻り値), _1: ref i64[] (v), _2: i64 (t), _3: i64 (i), _4: bool
  bb0: _2 = const 0; _3 = const 0; goto bb1
  bb1: _4 = lt(_3, len(*_1)); branch _4 bb2 bb3
  bb2: check _1; _2 = add(_2, (*_1)[_3]); _3 = add(_3, 1); goto bb1
  bb3: _0 = copy _2; return
```

- **変数（local）**: 番号と具体的な型を持つ。引数・ローカル変数・一時値すべて。
- **場所（place）**: `_3`、`(*_1).x`、`_2[_4]` のように、変数からのたどり方。今のインタプリタの `Place`（スロット＋道筋）と同じ考え。
- **値の読み方は 2 つ**: `copy 場所` と `move 場所`。今の `eval`（ムーブする）と `eval_borrow`（しない）の区別を、ここで確定させる。
- **命令**

| 命令 | 意味 |
|---|---|
| `場所 = 式` | 式は、読む・計算・`as`・構造体を作る・`ref 場所`・`own 値`・呼び出し・`show`（表示用の文字にする）・組み込み（print など） |
| `drop _n` | 変数の寿命の終わり。中の own を型にそって全部解放し、変数の場所も解放する（借りられていた変数なら世代が進む）。ムーブ済みなら何もしない |
| `discard 値` | 値を捨てる（式文の値・`drop(x)`） |

- **世代チェックは場所の中に書く**: `(*!_1)` は「`_1` の先をたどる。世代チェックあり」、`(*_1)` は「解析で消せた」。
  独立した `check` 命令にしないのは、チェックがいつも「たどる」ことと一組だから（実装して決めた）。
- **ムーブ**: `move _n` で読むと変数は空になる。空の変数を読めば実行時エラー（今のインタプリタと同じ）。
  LLVM ではこれを「ムーブの印」（drop フラグ）にする。印が要るのは一部の道でだけムーブされる変数だけ（7 で決める）。
- **終わりの命令（各ブロックの最後）**: `goto`・`branch`（真偽）・`return 値`・`step`（`for range` の次の周回。型の範囲を超えたら抜ける）・
  `fail`（実行時エラー。位置を持つ）。enum の `switch` は 5 で足す。
- **呼び出し**: 名前のある関数（単相化した名前 `max<i64>`）・関数の値（クロージャ）・interface のメソッド（vtable）の 3 通り。

### ムーブと解放の書き出し（いちばん大事なところ）

- スコープの終わり・`break`・`return`・`?` で抜けるとき、そのスコープの変数に内側から `drop` を出す（ムーブ済みなら何もしない）。
- **一部の道でだけムーブされた変数**（`if` の片方でだけ渡したなど）は、「まだ持っているか」を表す隠れた bool の変数（drop フラグ）を置き、
  抜けるときにそれを見て `drop` する（Rust と同じ方法）。今のインタプリタは実行中に `Moved` を見ていたが、IR では実行前に決める。
- `match` で受け取る名前・`for` の変数・クロージャの取り込みも、今のインタプリタの動き（どこでムーブ・どこで写し）をそのまま命令にする。

## 実行時の値の形（LLVM で使う形。IR の型もこれに合わせる）

| 型 | 形 |
|---|---|
| 整数・f64・bool | そのまま（あふれは一周。LLVM の普通の足し算と同じ） |
| `own T` | ヒープの区画へのポインタ。区画の頭に **世代**（64 ビット）を置く |
| `ref T` | （指す先のアドレス, 区画の頭のアドレス, 借りたときの世代）の 3 つ組。指す先がフィールドや配列の中でもよい |
| 構造体・配列 | 中身をそのまま並べる（C と同じ並べ方） |
| enum | 種類の番号＋中身（いちばん大きい種類の大きさ） |
| リスト | （要素の領域, 長さ, 容量）。要素の領域の前に世代（区画と同じ形）。要素を借りた ref はこの領域と世代を持つ（design-decisions.md の「リストの要素を借りる」） |
| 辞書 | 実行時ライブラリの表（入れた順を保つハッシュ表） |
| `str` | 書き換えない文字列を数を数えて共有（コピー＝数を 1 つ増やす。1 スレッドなので安全） |
| 関数の値 | （関数のアドレス, 取り込んだ値の区画） |
| `own I` / `ref I`（interface） | 上の形に、メソッドの表（vtable）のアドレスを足したもの |

- **解放した区画**: 同じ大きさの区画の置き場に戻すだけで、OS には返さない。世代は進めたまま残るので、古い ref は必ず検出できる（Vale と同じ考え）。
- **借りられる変数**（`ref x` と書かれた、own でない変数）: はじめは **ヒープの区画に置く**（今のインタプリタと同じで、確実に安全）。
  ref が関数の外へ出ないと解析で分かった変数だけ、あとでスタックに置く最適化をする。借りられない変数は普通の値（LLVM のレジスタ）。
- **実行時ライブラリ**: 区画の確保・解放、辞書、文字列の操作、print、入力は C で書き、clang で一緒にコンパイルする。
- **実行時エラー**: メッセージと位置（ファイル:行:列）を出して終了コード 1。通常の作り方では解放の記録も持ち、時系列を出す。

## 突き合わせの仕組み（3 で作ったもの）

- `src/ir/lower.rs` が構文木を IR にし、`src/ir/exec.rs` が IR を実行する。ヒープ・表示・計算は今のインタプリタのものを使う。
- デバッグビルドでは、`run_source` などが実行のたびに、書き出せたプログラムを IR でも実行し、
  **出力・エラーの題と位置・残ったヒープの数** を比べる。違えば panic するので、全テストがそのまま突き合わせになる。
- 入力（`read_line`）を読むプログラムは、テストが入力を文字列で渡したとき（`run_source_with_input`）だけ比べる（同じ入力をもう一度流す）。
  `jabberwock --ir` は、書き出せないときに理由を出す。

## 5 で決めたこと（実装して分かったこと）

| 項目 | 決めたこと |
|---|---|
| enum の中身 | `switch` で種類に分かれ、`take (x as Some).0` で受け取る名前へ移す。借りた match は中身の own を ref で受け取る |
| `?` | Err / None の道で、まだ使っていない一時的な値と全部の変数を drop してから、その値を返す |
| 添字 | 場所の一部（`Proj::Index`）。添字は場所をたどる前に計算しておく（interp と同じ順） |
| for x in a | 始めた時点の要素の写し（中の own は読むだけの ref）を隠れたリストに置いて回す |
| ジェネリクス | 型の引数ごとに関数を作り分ける（`pick<i64>`）。interface の条件で呼んだメソッドも具体的な構造体のメソッドになる |
| interface を型として使う | その名前のメソッドを持つ構造体の表（vtable）から、値の構造体名で選ぶ（`dyn`） |
| クロージャ | 本体は別の関数。取り込んだ値は呼ぶときに読むだけの写しで最後の引数として渡す |
| 値で決める読み方 | 関数の値（取り込んだものしだいでムーブ）と、取り込んだ変数は `read`。LLVM の前に、クロージャをいつもコピーにする案（仕様の変更）を相談する |

## 7 で決めたこと（実装して分かったこと）

| 項目 | 決めたこと |
|---|---|
| ファイル | `src/ir/llvm.rs`（IR → LLVM のテキスト）・`runtime/jw_rt.c`（実行時ライブラリ）・`src/native.rs`（clang を呼ぶ） |
| 変数 | スタック（`alloca`）。`ref x` で変数そのものを借りる変数だけ区画（ヒープ）に置く。変数ごとに「状態」（値がある・まだない・ムーブした位置）を持ち、ムーブ済みを読むとエラー |
| own | 区画の中身へのポインタ。区画の頭 16 バイトに世代と「最後に解放した位置」 |
| ref | （指す先, 区画, 世代, 借りた位置）の 32 バイト。interface の ref は構造体の番号を足して 40 バイト |
| own の読むだけの写し | for の要素などは、下の 1 ビットを立てたポインタで「写しの札」（区画・世代・借りた位置）を指す。先をたどるときに世代を確かめる。型の形が変わらないので、メソッドにもそのまま渡せる |
| interface の own | （ポインタ, 構造体の番号）。メソッド・表示・解放は番号で分かれる |
| 型ごとの手伝いの関数 | 解放・複製・写し・表示・比べる・取り出せるか、を使われた型の分だけ作る |
| 文字列 | 数を数えて共有。定数は数えない（rc = -1） |
| match で取り出した入れ物 | 同じブロックで `take` した入れ物の `drop` は、中身を解放しない（中身はもう受け取る名前のもの） |
| 小数の表示 | Rust の `{:?}` と同じ（いちばん短く元に戻る桁。ちょうど真ん中なら大きいほう）。6 万個の値で Rust と比べて一致 |
| 関数の値 | （入口, 取り込んだ値の入れ物）。入れ物は数を数えて共有し（取り込んだ値は書き換えないので複製は共有でよい）、頭に「ムーブする・own を持つ・元がムーブするものだった」の印。入口 `@tramp` が読むだけの写しを作って本体を呼ぶ。今の仕様（own を取り込んだ関数の値はムーブ）は印を見て決める |
| sort_by | interp と同じく、要素の写しを先に作り、添字の並びを比べる関数で並べてから要素を動かす（比べる順も interp と同じ） |
| 突き合わせ | `JW_NATIVE=1 cargo test` で、書き出せたプログラムを実行ファイルにして、出力・エラー表示（全文）・残った区画の数を比べる |
| 実行時エラーの表示 | interp の `render_in` と同じ形。ソースは実行ファイルに入れ（`@jw_files`）、位置の札 `WSite.fileno` がファイルの番号。実行時ライブラリが位置を集めて並べて出す。`--release` はソースを入れず、使った位置だけ |
| 解放の位置 | 区画の頭には最後の解放だけ。使い回すときに前の解放を輪の表（4096 件）に残し、ref の世代から「その ref を無効にした解放」を探す |
| 入力 | `read_line` / `args` は組み込み（`Rvalue::Builtin`）。突き合わせでは同じ入力を実行ファイルの標準入力に流す |
| スレッド | 区画の管理と呼び出しの深さはスレッドごと。待ちは 1 組の錠と条件変数（interp と同じデッドロックの数え方）。送る値は own の区画の世代を進め、文字列は複製する。spawn の関数は関数の値を作らず、入口 `@spawnN` から 1 回呼ぶ |
| `jabberwock build` | 一時フォルダに `.ll` と実行時ライブラリを書き、`clang -O2` で 1 つの実行ファイルに。Windows は起動時に端末を UTF-8 にし、引数を UTF-16 から読む（`-lshell32`） |

## 推測・未確定

- `ref` を 3 つ組にすると大きい（24 バイト）。解析で検査不要と分かった ref を細くできるかは、7 のあとに測って決める（推測: 多くの関数の引数は細くできる）。
- 辞書の中身の作り（今は「並び＋表」）は、実行時ライブラリを書くときに決め直す。
