# 安全性検証 1〜7 の合格基準

この文書は docs/safety-testing.md の項目1〜7について、実装を直した箇所、検証方法、判定条件をまとめる。
テストを追加したことと、そのテストが実際に成功したことは分ける。実行結果は末尾に記録する。

2026-10-26追記: [形式仕様と退役](formal-semantics.md) の抽象モデルの証明を別途追加した。
世代上限での退役は後続の変更で実装した。[退役変更の再検証](generation-retirement.md) と以下の既存実装についての合格やテスト本数を分ける。
既存1〜7の位置づけ、残課題8/9、5保証に向けた追加課題と合格条件は [検証体系](verification-plan.md) を参照する。

## 判定条件

| 項目 | 合格に必要な確認 |
|---|---|
| 1. 検査を消す解析 | 生成入力ごとに AST・IR とネイティブを解析あり／なしで実行し、出力・エラー全文・正常終了時の残存区画数を比較。ASan/UBSan の -O1 と -O2＋LTO の両方で成功する |
| 2. 型の通る攻撃 | 共通の攻撃78件を全件実行。型エラー・未対応によるスキップを認めず、操作到達の印と期待する診断を確認。リスト操作13種、own の無効化、分岐・ループ、添字の読み書き・借用を含む |
| 3. データ競合 | C と生成LLVMの競合負例をTSanが検出する。threads・native・systemを3回以上反復。入れ子spawn・出力・ownの送受信と別スレッドでの解放も成功する |
| 4. 生成LLVMの未定義動作 | 除算・剰余・シフトの守りを検査。390モジュールでアドレス・整数演算に未証明の前提がないこととLLVM verifierの成功を確認。演算の端76件とアドレスの攻撃を解析あり／なしで実行する |
| 5. 最適化 | 同じ比較器と攻撃ケースを -O1 および -O2＋LTO で実行。ASan/UBSan の全体試験も成功する |
| 6. 未初期化メモリ | MSanが生成LLVMの未初期化値をCへ渡す負例を検出する。通常・攻撃・生成入力の全体試験に加え、jwc生成物もMSanで成功する |
| 7. 自己ホスト版 | jwcの `--ll` 出力を `native` 経路で実際に計装し、Rust版の解析あり／なしと比較。全攻撃78件・演算の端76件・生成入力をASan/UBSanとMSanで実行する。既存のjwc buildの試験も成功する |

生成入力には別途、実行比較した本数と型エラーだった本数を報告する。
攻撃78件と演算76件にはスキップがない。負例は意図的に不正なLLVM/Cをテスト内だけに挿入する。
その負例で期待するsanitizer報告が出ることを成功とする。言語の通常実装に不正な命令を加えるものではない。

## 今回修正した検査漏れと実装

- `run_source_with(..., false)` の「解析なし」は、従来デバッグ用IR比較とスレッド内IRの再構築では解析していた。
  その2経路にも設定を伝え、実際に検査を消さないIRと比較する。
- `g_threaded` はspawnのたびに書く共有フラグだった。既に動いているスレッドが出力時に読むため、同じ1を書いても競合する。
  不可分の読み書きに修正。修正前の実行時ライブラリに入れ子spawnの入力を与えると、TSanで競合を再現した。
- 送信前に借りた古いrefの世代検査が、受信側での解放・再利用と競合する問題をTSanで再現した。
  区画ヘッダーへのアクセスをCと生成LLVM（Rust版・jwc版）ですべて不可分にする。
  世代を書き換えるのは唯一の所有者だけで、別スレッドに残る無効なrefは読むだけなので、relaxedのload/storeで足りる。
  `tests/safety/sent-*-reuse.jw` の3経路をTSan・ASan/UBSan・MSanで検証し、ヘッダーの非atomicアクセスをLLVM監査でも拒否する。
- MSan付きC関数は引数を `noundef` として扱う。生成LLVMの外部宣言にその約束がないと、
  未初期化の数を渡してもC側で初期化済みと扱われ、検出できない場合があった。
  MSanを選んだときだけ外部宣言の引数にも同じ属性を付け、呼び出し前に検査させる。負例で出力への受け渡しも検出する。
- jwcのbuildは `JW_CFLAGS` を読まないため、以前の比較は自己ホスト生成物のsanitizer試験になっていなかった。
  比較器はjwcが生成したLLVMを取得し、Rust版と同じ計装・コンパイル経路を使う。
- Windowsではjwcの `-lm` 指定、計測版の `dprintf`、パッケージの出力名の `.exe`、改行形式に問題があった。
  対象OSをclangのプリプロセッサで調べ、MSVC/MinGWのスタック指定を分ける。計測出力はCの `fprintf` を使い、COFFで実行されない場合がある `llvm.global_dtors` に依存せず、`jw_main` の正常終了時に呼ぶ。
  `.exe` をキャッシュ判定にも使い、ソースの改行をLFに固定する。パス表記だけを比較するテストは区切りをそろえる。
- jwcのLTO再試行では、引数リストをムーブせず複製する。LTOを拒否するclangラッパーを使った回帰テストで、通常リンクに戻って実行できることを確認する。

## LLVM のアドレス計算の確認

`src/ir/llvm.rs` と `jwc/llvmfn.jw` / `jwc/llvm.jw` で生成する命令を用途別に確認する。
CのUBSanだけでは、手書きしたLLVMの未定義動作全体の検査にはならない。

| 経路 | 根拠と検査 |
|---|---|
| 配列・リストの添字 (`FnGen::place`, `index`) | 符号付きは負数と長さ以上、符号なしは長さ以上を分岐で弾き、失敗側は `unreachable`。その後でGEPし読み書き・借用する。負数・最大整数・空リスト・多次元・書き込み・refの攻撃で確認 |
| リストの操作 (`seq_op`) | 位置はruntimeの範囲検査を通し、要素を動かす前後の世代を更新する。pop・drain・sort等の後の古いrefを全操作別に実行して診断を確認 |
| 構造体・enumのフィールド | 型検査／単相化で決めた構造体型と固定フィールド番号を使う。enumの中身は種類の分岐後に扱う。既存のstructs/enums/generics/interfaces/native試験と全体ASan/MSanで確認 |
| clone/drop/show/比較のヘルパー | 型で決めたフィールド、または長さを上限とする生成ループで処理する。所有値、写し、空の値、複合値の既存native試験をsanitizer付きで実行 |
| クロージャ・spawnの環境 | 生成する型の `sizeof` と同じ型のGEPを使う。引数と戻り値の置き場はruntimeが確保し、スレッドをまたぐ値はsend処理を通す。入れ子spawnと所有権移動をTSanでも確認 |
| 世代ヘッダー・写しのタグ | ヘッダーの固定オフセットとタグ除去を専用の補助関数で扱う。区画再利用、別スレッドでの解放、要素参照の無効化を試験する。内部で保持する解放済み区画はASanだけに頼らず、期待する言語エラーも照合する |

GEPに `inbounds` を付けず、整数の一周する演算に `nsw` / `nuw` / `exact` を付けない。
float→整数は生の `fptosi` / `fptoui` を使わず、境界とNaNを扱うCの `jw_f2i` に渡す。
除算の0と符号付きの最小値/-1、幅以上・負数のシフトは既存の守りと76件の実行比較で確認する。
これらの前提を変える変更は、形の検査と対応する実行試験を同時に更新する。

## 言える範囲

合格後に言えるのは「上の言語機能と実行構成について、参照無効化・範囲外アクセス・データ競合・未初期化値を検査し、
定義した試験をすべて通過した」ということ。あらゆる将来の入力についての数学的な証明ではない。
変更後もCIの負例・固定攻撃・生成入力を継続し、不一致を見つけたら再現入力を回帰テストに加える。

時間・メモリの使い切り、ファイルやコマンドへのアクセス制限はこの判定に含めない。
第三者のプログラムを実行するサービスには、OS側で時間・メモリ・ファイル・ネットワークを制限する仕組みが必要。
docs/safety-testing.md の項目8・9も別に残っており、「第三者コードを無制限に動かして安全」とは判定しない。
