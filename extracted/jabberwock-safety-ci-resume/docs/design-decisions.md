# 設計の決めごと

## 世代の周回を禁止し、上限で区画を退役させる（2026-10-26）

オーナーの指示で言語仕様の形式化を開始し、退役の仕様変更を採用した。
旧決定の「u64の周回には長い時間がかかるので退役しない」は撤回する。
実用上の時間の長さを、古いrefが復活しないという無条件の数学的性質の根拠にしない。

- 世代は周回禁止。状態bit・送信時の加算・リストの更新も含め、表現可能な上限を超える前に退役する。
- 退役したkeyは再利用しない。古いrefから検査用metadataを安全に読めることも維持する。
- 使用を継続する値は新しいkeyへ所有責任を移すか、安全に継続できなければ資源エラーで停止する。
- 論理世代・退役・ムーブの抽象モデルをLean 4で機械検査する。実装や最適化との対応は別に証明する。

詳細は [形式仕様](formal-semantics.md)、採用した言語規則は [spec.mdの7.2](spec.md#72-ref世代つき参照)。
仕様・形式モデルに続き、Rust/IR/C/native/jwc本体へ退役を反映した。詳細は [実装と再検証](generation-retirement.md)。
解放時の上限は再利用せず保持し、生きたC区画の上限は規定の資源エラーで停止する方式を採用した。
この変更だけで既存の1〜7や残課題8・9の判定範囲を拡大しない。

文法・言語仕様について決めたことの記録。「仮」は後で変えてよいもの。

## 入れ子の深さと文字列の長さの上限（2026-10-25。外部レビューで見つかった強制終了から）

- 括弧を 1 万段重ねると、構文解析の再帰でスタックがあふれてコンパイラごと落ちていた。利用者のコードを動かすサービスでは、細工した入力で処理系を止められる。
  構文解析で入れ子（式・ブロック・型・形を合わせて数える）を 256 段までにし、超えたら「入れ子が深すぎます」のエラーにする。
  型検査・解析・実行・書き出しも入れ子をたどる再帰なので、入口の構文解析で止めれば後ろの段も守られる。ふつうのプログラムは 256 段に届かない
  （深い if は 1 段で 2 つ数える）。コマンド（jabberwock・alice）は、構文解析も含めて全体を大きなスタック（1 GiB）で動かす。
- `"abc".repeat(9223372036854775807)` は、長さの掛け算があふれて Rust 版が panic していた（実行ファイルは止まらずに回り続けた）。
  確保の前に「長さ × 回数 ≦ 2^62 バイト」を確かめて実行時エラーにする（2^62 は jw_rt.c の区画の大きさの計算があふれない値）。
  上限の中でも確保できないときは、interp は「メモリが足りません」のエラー、実行ファイルは内部エラーで止まる（メモリの上限そのものは、まだ決めていない）。
- 同じ種類で `[0; 9223372036854775807]` も、Rust 版が panic し、実行ファイルはスタックがあふれていた。固定長の配列は値で、実行ファイルではスタックに置く。
  なので、配列 1 つの大きさを 1 MiB までにし、型検査でエラーにする（オーナーがカードで選択）。大きいものはリストで持つ。
- 堅牢性テスト（tests/robust.rs）で、`1 + 1 + ... + 1`（1 万個）や `x.abs().abs()...` の長い鎖でもスタックがあふれると分かった。
  構文解析は繰り返しで読むが、できる木は左に深く、後ろの段が再帰でたどるため。演算子・`as`・`.` / `[` / `?` の鎖も 1 つごとに入れ子として数える
  （同じ 256 段の上限。ふつうの式は届かない）。
- 同じテストで、型検査の上限（2^59）の中の `[0; 9236854775807]` のリストで interp が確保に失敗して落ちると分かった。
  repeat と同じく確保の前に確かめて「メモリが足りません」の実行時エラーにする。大きな `[x; n]`（2^20 より多い）は IR に書き出さない（実行ファイルは 64 より多いと書き出せない）。
  大きさは 8 バイトの数で数え、中の構造体・enum（いちばん大きい種類 + 1）も数える。`[x; n]` のリストは 2^62 バイトまで。
  数えるのは型を書いた所と配列の式だけ（ジェネリックな構造体の型の引数に大きな配列を入れると数え漏れうる。実行ファイルのスタックは 8 MiB）。

## 数値などの値渡しだけの直接呼び出しと要素 ref（2026-10-25）

- IR の解析は、取り込みがなく、全引数と戻り値が数・真偽・文字列・値なしの直接呼び出しでは `RefElem` を残す。
  参照・所有値・リスト・構造体・enum・関数値・チャンネルなどは対象外。暗黙の this と取り込みも見落とさない。
- 理由: 今の言語には可変のグローバル変数がなく、この形の呼び出し先には呼び出し元のリストに届く経路がない。
  純粋関数とは限らない（print やエラーはありうる）。引数を評価しているあいだの無効化も従来どおり反映する。
- 基本ブロックの固定点計算と検査を書き込む処理の両方で同じ判定を使う。関数値と interface の呼び出しは従来どおり事実を消す。
- 自己ホスト版 `jwc/analyze.jw` にも同じ判定を入れ、Rust 版との IR・LLVM の一致を保つ。
  言語の意味、借用印、ref の表現、AST の解析は変えない。
  証明の前提・測定・テスト・Claude 向けの確認事項は [実装引き継ぎ](scalar-call-handoff.md) にまとめる。

## 型

- **型推論は関数の中だけ**（Rust・Go・Swift と同じ）。関数の引数と戻り値には型を書き、`let` は推論する。
  - 理由: ネイティブコードを出すには型が要る。エラーを「食い違った場所の近く」で出せる（親切なエラーが看板）。
- `own` と `ref` は型の一部（例: `fn inc(ref i64 r)`）。
- **型の名前は Rust と同じ（仮）**: `i8` `i16` `i32` `i64` `u8` `u16` `u32` `u64` `usize` `f32` `f64` `bool` など。
  - 型を書かない整数リテラルは `i64` になる。
- 実装状況: 実装済み（2026-10-23）。使える型は整数（i8〜i64、u8〜u64、usize）・`bool`・`str`・構造体・`own T`・`ref T`・`ref mut T`。（その後、f64・enum・配列・リスト・辞書・関数の型なども足した。今の一覧は spec.md の 3.1。f32 はまだ）
  - 文字列の型は 1 種類だけで `str`（Rust の String と &str の使い分けはしない）。
  - 構造体のフィールドは `struct Point { i64 x; i64 y; }`（「型 名前;」）。
  - 推論は前から順に決めるだけ（Go の `:=` と同じ）。双方向の推論はしない。
  - `ref mut T` は `ref T` が要るところにそのまま渡せる（逆はできない）。
  - 戻り値のある関数は、本体の最後の `;` のない式が戻り値（`return 値;` でもよい）。値を返さないまま終わる道があるとエラー。
  - 構造体が自分自身を（own を通さず）じかに含むのはエラー（大きさが無限になるため）。
  - 型の違反と mut / ref mut の違反は実行前のエラー。
- **ref の型に寿命（ライフタイム）は書かない。** 安全は世代付き ref で守る（Rust が難しい一番の理由を持ち込まない）。
- **整数の変換**: 値が欠けない変換（i32 → i64、u8 → i16 など）は自動、欠けうる変換は **`x as u8`** で明示する（Rust 風。2026-10-23 に決定）。
  - `as` で範囲の外の値にしたときは一周する（300 as u8 は 44）。あふれと同じ決まり。
  - `as` は前置演算子（`-` `*`）より弱く、`*` や `+` より強い。`-1 as u8` は `(-1) as u8`。
  - 型の違う整数どうしの演算は、片方へ欠けずにそろえられるなら広い方の型でする（u8 + i64 は i64）。そろえられない（i32 と u32 など）ならエラーで、`as` を使う。
  - `usize` は環境で幅が変わりうる型として扱い、自動で受け取るのは u8 / u16 / u32 からだけ。u64 とは別の型。
  - ref や own の中の型は変換しない（`ref u8` は `ref i64` として渡せない）。
- **数の書き方は使う先の型に合わせる**: `let u8 b = 200;`、`b + 1` の `1` は u8。型が決まらなければ i64。
  - そのまま書いた数が型に入らないならエラー（`let u8 b = 300;`）。計算した結果が入らないなら警告（`200 + 100` を u8 に）。
  - for の range は、始めと終わりを同じ型にそろえ、それがループ変数の型になる。刻みはいつも i64（負の刻みのため）。
  - 符号なしの型に `-` はつけられない。
- **整数のあふれは一周する**（Go や Rust のリリース版と同じ。C++ の未定義動作と違い、結果は決まっている）。
  - コンパイルの時点で値が分かる計算（定数どうし）があふれるときは警告を出す。実行は止めない。
  - 変数の値しだいで起きるあふれは実行前には分からないので、警告できない。
    あふれを確かめたい場面のために、あとで `checked_add` のような明示的な関数を用意する（未実装）。
  - 0 で割るのは実行時エラー（定数なら警告も出す）。

## 型の書き方: どこでも「型 名前」の順（Java 風）

```
fn i64 add(i64 a, i64 b) {          // fn、戻り値の型、関数名、引数は「型 名前」
    return a + b;
}
fn ref Player find(ref World w) { ... }
fn main() { ... }                   // 戻り値なしは型を省く

let i64 x = 5;                      // 変数に型を書くときも「型 名前」
let y = 5;                          // 普段は省略して推論（i64）
```

- パースの規則: `fn` のあと、すぐ後ろに `(` が来る名前が関数名。その手前が戻り値の型（なければ戻り値なし）。
  `let` も同様に、すぐ後ろに `=` が来る名前が変数名で、その手前が型。
- 欠点: 「fn add」で検索できない（`add(` で探す）。

## 分岐とループ

決まったこと:

- **do-while はなくす。**
- **三項演算子 `? :` はなくす。**
- **for-else を入れる。** `else` はループの本体が **0 回** だったときに実行される。
  - 注意: Python の for-else（break せずに終わったときに実行）とは意味が違う。エラーメッセージやドキュメントで明示する。
  - キーワードは `else` のまま（直感的なため。2026-10-24 に見直したうえで残した）。代わりに、else のある for の本体に break があると警告する
    （Python に慣れた人が「break しなかったら else」と読み違えるのはこの形だけ）。

- **`loop`（無限ループ）は残す。**
- **switch は `match` という名前にする。**
- **for は Python と Rust を混ぜた形**: `for i in range(1, 10, 2) { }`
  - `range(終わり)` / `range(始め, 終わり)` / `range(始め, 終わり, 刻み)`。終わりは含まない（Python と同じ）。
    例: `range(1, 10, 2)` は 1, 3, 5, 7, 9。逆向きは `range(10, 0, -1)`。
  - 理由: Rust の `(1..10).step_by(2)` は直感に反する。
  - for-else と組み合わせられる（`range(5, 5)` のように 0 回なら else）。

- **if は式。** 文としても書けるし、値としても使える（三項演算子の代わり）。
  ```
  if x > 0 { print("正"); }              // 文として
  let m = if a > b { a } else { b };     // 値として
  ```
  - 値として使うときは else が必須。値はブロックの最後の `;` のない式。
- **条件は `( )` で囲まない**（if・while・for・match 共通）。`{ }` は必須。
  - そのため条件の中に構造体リテラルを直接は書けない（`{` があいまいになる）。括弧で囲めば書ける。

- **while は残す。** ループは `loop`（無限）・`while`（条件つき）・`for`（範囲）の 3 つ。
- **break / continue を入れる。**
  - 値として使う if の中からは、return と外のループへの break / continue はできない（今のところ）。
- **match は Java の switch（矢印形式）にそろえる。** 文としても値としても使える。
  ```
  match n {                          // 文として（default がなくてもよい）
      case 0 -> print("zero");
      case 1, 2 -> print("small");
      case 3 -> {
          print("three");
      }
  }
  let name = match n {               // 値として（default が必須）
      case 0 -> "zero";
      case 1, 2 -> "small";
      default -> "many";
  };
  ```
  - fall-through はない（Java の矢印形式と同じ）。値はブロックの最後の `;` のない式（if 式と同じ。Java の `yield` は不要）。
  - case に書けるのは整数・真偽値・文字列のリテラル（のちに enum の種類と、形を重ねたものも。下の「enum と Option」「match の形を重ねる」）。同じ値の case が二回あるとエラー。
  - 値として使う match には default が必須（true と false を両方書いた場合を除く）。中から return / 外への break はできない。
  - 矢印の記号 `->` は仮。差し替えるかもしれない。

実装状況: loop・while・for in range・for-else・break / continue・if 式・match は実装済み。

## 基本文法（2026-10-23 に決定）

- **変数は普段は書き換え不可。** 書き換えるものだけ `mut` をつける。並びは「型 mut 名前」。
  ```
  let i64 mut count = 0;    // 型を書くとき
  let mut total = 0;        // 型を推論するとき
  ```
- **null はない。** 「あるかもしれない値」は Option 型で表す。
- **列挙型 enum は Rust のように中に値を持てる。** Option や Result もこれで作る。match の網羅チェックの土台。
- **エラー処理は Result 型＋ `?`。** 例外（try/catch）はない。
- **メソッドは Java 風**（struct の中に書く）。細かい形は未定。
- **文の終わりには `;` をつける。**
- **`+=` などの複合代入と `++` / `--` を入れる。**
- 文字列の埋め込みは `"x = {x}"` の形（2026-10-23 に実装。`{ }` の中は式、`{{` `}}` で波かっこそのもの、中に文字列は書けない）。
- ジェネリクスは型が前なので `fn T max<T>(T a, T b)` のような形（細部は未定）。
- 文字型・`const` はこれから（配列・添字・モジュール・`pub` はのちに実装。`as` は整数の変換として決定済み）。

実装状況: `mut`・`ref mut`・`;`・複合代入・`++` / `--` は実装済み（`let mut x` / `let i64 mut x` の両方。違反は実行前のエラー）。
Option と enum・ジェネリクス・Result と `?`・メソッドは実装済み（下にそれぞれの節）。文字列の埋め込みも実装済み。

## 細部（2026-10-23 に決定）

- **A. ブロックの値は、最後の `;` のない式**（Rust と同じ）。
  ```
  let v = if ok { let t = 2; t * 3 } else { 0 };   // 6 か 0
  let w = if ok { 1; } else { 2 };                 // エラー: `;` を外すと値になる
  ```
  - `}` で終わる文（if・while・for・loop・match）のあとには `;` は要らない。
  - match の矢印の後ろが式なら `;` で終える（`case 0 -> "zero";`）。`{ }` なら要らない。
  - 改行はただの空白。式を途中で改行してもよい。
- **B. 借用は `ref`（読むだけ）と `ref mut`（書き換えてよい）の 2 つ。**
  - `ref mut` で借りられるのは mut の持ち主（`let mut` の変数、または `ref mut` の先）だけ。
  - `ref mut` から `ref` に借り直すのはよい。逆（`ref` から `ref mut`）はできない。
  - 書き換えられるかは持ち主で決まる。構造体のフィールドも、own の先も、持ち主が mut でなければ書き換えられない。
  - 同時に何個 `ref mut` があってもよい（Rust のような「1 個だけ」の制限はない。安全は世代付き ref で守る）。
- **C. メソッドは Java 風で `this` は書かなくてよい**（暗黙）。`this` を書き換えるメソッドは `fn mut 名前()` のように印をつける。実装済み（下の「メソッド」）。
- **D. `++` / `--` は文だけ。** `print(i++)` のように式の中には書けない（前置・後置の違いで迷わないため）。

## enum と Option（2026-10-23 に決定・実装）

```
enum Shape {
    Circle(i64 r);
    Rect(i64 w, i64 h);
    Empty;
}
let s = Shape.Circle(5);
let i64 area = match s {
    case Circle(r) -> 3 * r * r;
    case Rect(w, h) -> w * h;
    case Empty -> 0;
};
fn Option<i64> find(i64 n) { ... }
let x = Some(5);
let Option<i64> y = None;
```

- 定義は構造体と同じ形。種類の中身は「型 名前」（引数と同じ）、種類の区切りは `;`。
- **値は `Shape.Circle(5)`（Java 風の `.`）。** Option だけは前に何もつけず `Some(x)` / `None`。
- **match の case は種類の名前だけ**（`case Circle(r)`）。受け取らない中身は `_`。
  - 種類をまとめた case（`case Circle(_), Rect(_, _) ->`）では中身を受け取れない。
- **enum の match は、全部の種類を書かないとエラー**（文としての match でも）。default でまとめてもよい。
  新しい種類を足したときの書き忘れを実行前に見つけるため。
- 中身に own や構造体を持ちうる enum は、値として読むとムーブ（構造体と同じ）。中身が数・bool・str・ref だけならコピー。
- `match x` は値の match（x がムーブなら x は使えなくなり、中身は受け取った名前へ移る）。
  `match ref x` / `match ref mut x`（x は own か ref）は借りるだけ。中身の own は `ref T` として受け取り、数などはコピーで受け取る。
  own を通さずに持つ構造体などの中身は、借りた match では受け取れない（`_` にする）。
- **Option は `Option<T>`。** ジェネリクスが入ったので普通の enum（最初からある定義）に置き換えた。
  - `None` の型は、入れる先の型から決める（`let Option<i64> x = None;`、戻り値、引数、if の then 側など）。決まらなければエラー。
- enum どうしの `==` はまだない（match を使う）。
- 構造体と同じく、自分自身をじかに含む enum はエラー（own を通す）。

## ジェネリクス（2026-10-23 に決定・実装）

```
fn T pick<T>(bool first, T a, T b) { if first { a } else { b } }
struct Pair<T> { T a; T b; }
let x = pick(true, 1, 2);
```

- **型の引数は名前のあとに `<T>`**（関数・構造体・enum）。関数の戻り値の型は前（`fn T pick<T>(...)`）。
- **使うときに型の引数は書かない。** 引数・フィールド・入れる先の型から決める（前から順に決めるだけ）。
  - 数どうしは欠けずにそろう広い方。数の書き方と `None` は、ほかで決まった型に合わせる（後回しにして調べる）。
  - 決まらなければエラー（`let x = nothing();` など）。そのときは入れる先の型を書く。
- **型の名前として書くときは型の引数を省けない**（`Pair<i64>`）。
- **`T` でできることは「渡す・返す・しまう・print」だけ。** 計算や比較を許す仕組み（Rust の trait / Go の制約のようなもの）はまだ決めていない。
- ムーブかコピーかは中身しだい（own や構造体ならムーブ）。型の分からない関数の中で作った enum の値は、実行時に中身を見て決める。
- `Option` は最初からある `enum Option<T> { Some(T value); None; }`。`Some(x)` / `None` は短い書き方として残す。

## Result と `?`（2026-10-23 に決定・実装）

- **例外はない。** 失敗は `Result<T, E>` で返す（最初からある enum `enum Result<T, E> { Ok(T value); Err(E error); }`）。
- `Ok(x)` / `Err(e)` は `Some` / `None` と同じく、前に何もつけずに書ける。
- **`e?` は Rust と同じ。** Err ならそのまま関数から返す。Option にも使える。
  - Err の型の自動変換（Rust の `From`）はしない。型が違えばエラー（match で作り直す）。
  - 式の途中でも使える。抜けるときは、途中まで作った引数・構造体・変数の own をすべて解放する。

## メソッド（2026-10-23 に実装）

- 構造体の中、フィールドのあとに `fn` で書く。書き換えるメソッドは `fn mut`（「C」で決めた形をそのまま採用）。
- `this.` は省ける（Java と同じ）。引数・ローカル変数が同じ名前ならそちらが優先。同じ構造体のメソッドも `len2()` と呼べる。
- `this` は `ref 構造体` / `ref mut 構造体`。`fn mut` を呼べるのは `ref mut` で借りられる相手だけ（mut の規則をそのまま使う）。
- **構造体の値（own でないもの）にもメソッドを呼べる。** 呼び出しのあいだだけヒープに移して借り、終わったら戻す。
  `this` を返すなどして借りた ref が残っても、戻した時点で無効になるので実行時に見つかる（安全は世代付き ref で守る）。
- **静的メソッドは Java 風に `static fn`、呼ぶときは `Point.at(1, 2)`。** 同じ構造体の中からは `at(1, 2)` でよい。
- まだないもの: enum のメソッド。

## 型の引数につける条件（2026-10-23 に決定）

- **Go 風。** `interface Shape { fn i64 area(); }` を書き、`fn i64 total<T: Shape>(ref T s)` のように条件をつける。
  メソッドがそろっている構造体は、何も宣言しなくても当てはまる（`implements` は書かない）。
- 数や文字列の比較は組み込みの条件 `<T: ordered>`（整数・str）で書く。これに合わせて str どうしの `<` なども使えるようにした（辞書順）。
- 条件は呼び出しの場所で確かめる（エラーは呼ぶ側に出る）。いくつもつけるなら `+`。
- 実装済み（2026-10-23）。
- **interface は型としても使える**（`own Shape` / `ref Shape` / `ref mut Shape`）。Go と同じく、当てはまる構造体なら何でも入る。
  そのままの値 `Shape` は書けない（大きさが決まらないので own か ref を通す。Rust の `dyn` と同じ考え）。
  元の構造体を取り出す方法（Go の型 switch）はまだ。

## 配列（2026-10-23 に決定・実装）

- 型は `i64[3]`（型が前の書き方に合わせて、長さは型のうしろ）。リテラルは `[1, 2, 3]` と `[0; 5]`（Rust と同じ）。
- **添字が定数なら、範囲の外は実行前のエラー**（Rust と同じ）。定数でなければ実行時エラー。
- 添字はどの整数型でもよい（Rust のように usize に限らない。`range` の i64 をそのまま使えるように）。`len()` は i64。
- 要素がコピーできればコピー、own を持てばムーブ。要素の own は取り出せず、借りるか置き換える。
- 伸び縮みするリスト、`for x in a` は下の「リスト」。

## リストと for x in a（2026-10-23 に実装）

- **リストは `i64[]`**（配列 `i64[3]` の長さなし）。`[...]` は入れる先の型が `T[]` ならリストになる。
- メソッドは `len()` / `push(x)` / `pop()`（`Option<T>`）。リストはいつもムーブ。
- **`for x in a` は借りて回す**（ムーブしない）。コピーできる要素はコピー、own の要素は `ref T` で受け取る。
  回すのはループを始めた時点の要素。ループの中で要素を取り出すと、その要素を借りた x は世代チェックで無効になる。
- `own` / `ref` は右側の型全体にかかる（`own i64[]` はリストの own）。own を要素に持つリストは `(own Node)[]`（型のかっこを足した）。
  逆（要素にかける）にするかはオーナーに確認中。

## own でない値を借りる・ref の引数は自動で借りる（2026-10-23 に決定・実装）

- 試しに書いたプログラムで一番困ったのが「own でない値を借りられない」こと（`docs/trial-findings.md`）。木のフィールドやローカルのリストを、いちいち own で包む必要があった。
- **変数・フィールド・配列の要素を、そのまま `ref` で借りられるようにした。** own を持つ場所は今までどおり own の先を借りる。
- 安全の仕組みは own と同じ世代チェック。インタプリタは変数もヒープのスロットに置き、ref は「スロット＋世代＋中の道筋（フィールド・添字）」を持つ。
  変数がスコープを抜ける・ムーブされると、スロットの世代が進んで ref が無効になる。
- **リストの要素の中は借りられない。** リストは伸び縮みして中の場所が変わる（LLVM では領域の取り直しで指す先がなくなる）ため。要素を借りたいときは `(own T)[]`。
  （2026-10-24 に変更: リストの要素も借りられるようにした。下の「リストの要素を借りる」）
  道筋が enum の中身を通ることもない（種類が変わると型が変わるため）。enum の中身を借りたいときは今までどおり own に入れる。
- **`ref T` の引数には、呼ぶ側で `ref` を書かなくてよい**（オーナーが A を選択）。場所を渡すと型検査が自動で借りる（`Expr.borrow`）。
  `ref mut T` の引数は呼ぶ側にも `ref mut x` と書く。書き換えられる引数が呼ぶ側で見えるように（Swift の inout の `&` と同じ考え）。
  一時的な値（`sum([1, 2])` など）は自動では借りない（今は型のエラー）。
  （2026-10-24 に変更: 一時的な値も借りるようにした。下の「一時的な値を ref の引数に渡す」）
- 構造体の値の変数に対するメソッド呼び出しは、ヒープへ貸すのをやめて、変数の場所を借りて `this` にした。

## 入力と文字列の操作（2026-10-23 に実装）

- 入力は組み込み関数 `read_line()`（`Option<str>`、入力の終わりで None）と `args()`（`str[]`）。CLI ではファイル名のあとの引数が `args()` になる。
  ファイルの読み書きはまだ（必要になったら足す）。
- 文字列はメソッドで操作する（`len`・`split`・`slice`・`to_int` など。一覧は spec.md 6.7）。
- **長さと位置は文字単位**（オーナーが決定）。バイト数は `byte_len()`（オーナーの案）。Python・Swift と同じで、日本語を途中で切る心配がない。
  位置を指定して取り出すのは長い文字列ほど遅くなるので、速さが要る所はあとでバイト単位のメソッドを足して補う。
- 文字型はまだないので、`chars()` は 1 文字の `str` のリストを返す。
- 数を文字列にするのは埋め込み（`"{x}"`）で足りるので、`to_str()` は作っていない。

## リストの insert / remove と、構造体の要素の for（2026-10-23 に実装）

- `insert(i, x)` / `remove(i)` を足した（試しに書いたプログラムで困った #3）。並べ替えは、比較を渡すクロージャのあとで考える。
- 構造体などコピーできない要素も `for x in a` で回せるようにした（#2）。x はループを始めた時点の要素の写しを、読むだけの ref で受け取る。
  写しの中の own は元の own を借りた ref にする（own は唯一の持ち主なので写せない）。元の要素が取り除かれれば世代チェックで見つかる。
  リストの中の場所そのものを借りないのは、リストが伸び縮みして中の場所が変わるため（own でない値を借りる、と同じ理由）。

## own と ref の表示（2026-10-23 に実装）

- print と埋め込みでは、own と ref は指している中身を出す（以前は `<own #3>` のようにスロット番号を出していた。#6）。
- 無効になった ref を出そうとすると実行時エラー（ほかの使い方と同じく、黙って変な値を出さない）。
- ref は輪になりうるので、表示は 32 段で打ち切る（`...`）。

## 小数 f64（2026-10-23 に実装）

- 型は `f64` だけ（`f32` はあとで）。書き方は `1.5`。
- 数の書き方は相手の型に合わせる、という整数の決まりを小数にも広げた。`let f64 x = 1;` は 1.0。
  数だけの式が小数の場所にあれば、中の数をすべて小数として計算する（`7 / 2` は 3.5。Go の型のない定数と同じ結果）。
- 整数と小数のまぜた計算は自動で変換しない（`as` で書く）。整数どうしの自動変換は値が欠けないときだけ、という決まりに合わせた。
- 0 で割っても IEEE 754 のまま（inf / NaN）。整数の 0 割りはエラーなので、ここは違う。
- `as` で整数にするときは 0 の方へ切り捨てて、型の幅で一周（整数の `as` と同じ「一周」の決まり）。
- 表示は `3.0` のように必ず小数点をつける（整数と見分けるため）。

## シャドーイング（2026-10-23 に決定・実装）

- **シャドーイングは禁止。** 同じ関数の中で、外のスコープや同じスコープにすでにある名前を、もう一度宣言できない（型検査の `declare`）。
  別々のブロック（兄弟のスコープ）で同じ名前を使うのはよい。
- **メソッドの引数・ローカル変数にフィールドと同じ名前はつけられない**（オーナーが A を選択）。メソッドの中の `x` はいつもフィールド。
  静的メソッドは this がないので対象外。
- **ねらい: ライフタイム修飾子をなくしたぶんの分かりにくさを、できるだけ補う。**
  名前がひとつの持ち主を指すので、「`r` がどの `a` を借りたか」がソースの見た目どおりになる。
  解析の根拠（`a` のスロットを解放できるのは `a` という名前の操作だけ）も、人が読んで同じように追える。

## クロージャ（2026-10-23 に決定・実装）

- **外の変数は値で取り込む**（オーナーが B を選択）。コピーできる値はコピー、ref は ref のまま、own はムーブ。
  取り込んだ ref は世代チェックで守られるので、ライフタイムを書かなくても安全（借りた先が先に消えれば実行時エラー）。
  - 自動で借りる案（C）は、クロージャが外の変数より長生きするかを型で追う必要があり、ライフタイムが戻ってくるのでやめた。
  - 取り込んだ変数は書き換えられない。写しを書き換えても外に届かず、見た目と動きがずれるため。外を書き換えたいときは `ref mut` を取り込む。
  - 取り込んだ own はクロージャのもの。何度も呼べるので、中から値として取り出せない（呼び出しのあいだは own を借りた ref の写しで使う）。
- **追加（2026-10-23。オーナーがカードで A を選択）: 関数・メソッドの引数にその場で書いたクロージャは、ムーブする外の変数を借りて取り込む。**
  `keys.sort_by((a, b) -> total[a] > total[b])` のあとも `total` を使える（試し書き 2 回目の #1）。
  - 借りるのは、コピーできない値（own・構造体・リスト・辞書など。関数の値と task は除く）。中では `ref T` として見える。
  - 変数に入れる・返す・enum に入れるクロージャと、`spawn` のクロージャは今までどおりムーブ。
  - 借りたクロージャを、借りた変数より長く持っていて呼ぶと、ダングリングの実行時エラー（世代チェックで守られる）。
  - いつも借りる案（B）は、変数に入れたクロージャが実行時に止まりやすくなるのでやめた。困った場面はどれも「その場で渡してすぐ呼ぶ」ものだった。
- 書き方は `(a, b) -> 式`。引数の型は、入れる先の関数の型から決める（Java / Kotlin のラムダと同じ。「前から順に決めるだけ」の型検査で足りる）。
- 関数の型は `fn R(A, B)`（関数の定義と同じ並び）。
- 変数に関数と同じ名前をつけるのは禁止（`f(x)` がどちらの呼び出しかを見た目で分かるように。シャドーイング禁止と同じ考え）。
- 並べ替え `sort()` / `sort_by(f)` も一緒に足した（#3 の残り）。安定なマージソート（2026-10-25 に下の「並べ替えの手順」へ切り替えた）。

## 取り出しながら回す（2026-10-23。オーナーがカードで A を選択。試し書き 2 回目の #2）

- `a.drain()`（全部の要素を新しいリストへ移し、a は空のまま残る）を足し、**その場で作ったリストを `for` で回すときは要素を値で受け取る** ことにした。
  場所（変数・フィールド）のリストを回すときは、今までどおり借りる。新しい文法は足さない（Rust の `drain` と同じ名前）。
- `take a` のように a をムーブする書き方（案 B）は、新しい文法が要り、変数を使い回せないのでやめた。
- 作り方: はじめに逆順にして、周回ごとに後ろから取り出す（前から取ると毎回詰め直しになるため）。あわせて `reverse()` も足した。
- 配列（`[a, b]` のまま型が配列のもの）は今までどおり借りて回す。

## map / filter と ok_or（2026-10-23。試し書き 2 回目の #4・#5）

- リストと配列に `map(f)` / `filter(f)`。f は要素を `for x in a` の x と同じ形で受け取る（新しい規則を作らない）。
  `filter` はコピーできる要素だけ（構造体などは、残す要素を複製するか元から取り出すかを決める必要があるため。`drain` と for で書ける）。
- `ok_or(o, e)` は関数（Option のメソッドではない）。enum のメソッドがまだないので、最初からある関数として足した（`lib.rs` の `PRELUDE`）。
  enum のメソッドを入れたら `o.ok_or(e)` も考える。

## enum のメソッド（2026-10-23。オーナーの了承「ではそれで作ってください」）

- 構造体のメソッドと同じ決まり（`fn` / `fn mut` / `static fn`、`this` は借りた ref）。enum の `{}` の中、種類のあとに書く。
- `Shape.x(...)` は x が種類でなければ静的メソッド。どちらでもなければ「種類 x はありません」のエラー。
- Option / Result に `is_some` / `is_none` / `is_ok` / `is_err` を足した（prelude に jabberwock で書いたメソッド）。
- まだしないこと:
  - this を値で受け取るメソッド（→ 下の `fn take` で対応した）。
  - enum を interface に当てはめること（enum の値は実行時に型の名前を持たないため。必要なら名前を持たせる）。
- 作り: enum の値は型の名前を持たないので、型検査が `MethodCall` の 4 つめに enum の名前を書き、interp はそれでメソッドを探す。
  IR / 実行ファイルは型が分かっているので、構造体と同じ形の呼び出しになる。

## this を値で受け取るメソッド `fn take`（2026-10-23。オーナーの依頼「1はあったほうが便利」）

- 書き方は `fn take 戻り値の型 名前(...)`。`fn mut`（借りて書き換える）と並ぶ印で、「this を受け取って使い切る」意味。
  `take` は予約語にしない（`fn take(...)` は take という名前のメソッド）。
- 呼ぶと receiver をムーブする（関数の引数に渡すのと同じ）。own / ref の先からは呼べない（取り出せないので型検査のエラー）。
- これで Option / Result に `unwrap_or`・`ok_or`・`map`・`ok` を足した（prelude に jabberwock で書いたメソッド）。
- interface のメソッドには当てはまらない（interface のメソッドは借りて呼ぶため）。
- 作り: 型検査が `MethodTarget.take` を立て、interp（`eval_take_method`）・analyze・lower は receiver を先に値として読む。
  関数の引数のクロージャの型の引数（`map<U>` の U）は、引数の型だけ渡して本体から決める（`instantiate`）。

## 複数行の文字列 `"""..."""`（2026-10-23。オーナーがカードで B を選択。試し書き 2 回目の #7）

- 改行を含む文字列は `"""..."""`（Python / Kotlin と同じ）。ふつうの `"..."` は今までどおり同じ行で閉じる（閉じ忘れをその行で知らせるため）。
- 開きの `"""` の直後の改行は含めない（1 行目から書き始められるように）。字下げは取らない（書いたまま）。エスケープと `{式}` の埋め込みはふつうの文字列と同じ。

## 値なしの型 `()`（2026-10-23。試し書き 2 回目の #6）

- 値を返さない task のリストを書くために、値なしの型を `()` と書けるようにした（Rust と同じ）。`task<()>[]`。
  関数の型は今までどおり `fn (i64)`（戻り値を書かない）。

## match の形を重ねる（2026-10-23。試し書き 2 回目の #3）

- `case Some(Op(op))` / `case Some(Op("-"))` / `case Add(Lit(0), r)` のように、中身の位置に種類・数・文字列・真偽値を書ける。
- 上から順に、形が全部当たった最初の case。調べるだけでは値を動かさない（当たったら中身を受け取る）。
- 中身の位置の名前は、大文字で始まれば種類の名前（`Some(End)`）。種類の名前は大文字で始める慣習に頼る（型を見ずに構文だけで決められる）。
- 値の match で own の中に重ねるのは禁止（own の入れ物から中身だけ取り出すことになり、決まりが増えるため）。借りた match ならよい。
- 全部書いたかの判定は「同じ種類の case が 1 か所だけ重ねている」ときに中までたどる（それ以外は default が要る。安全側）。

## 辞書（2026-10-23 に決定・実装）

- **型の書き方は `V[K]`**（オーナーが A を選択）。`i64[]`（リスト）・`i64[3]`（配列）と同じく、後ろに `[ ]` をつける形にそろえた（D 言語と同じ）。
- 作り方は `["a": 1]`、空の辞書は入れる先の型が辞書なら `[]`。
- **入れた順に回る**（Python と同じ）。出力が実行ごとに変わらないので、テストやデバッグがしやすい。
- キーは整数・`str`・`bool` だけ（構造体のキーは、等しさとハッシュの決まりを interface で決めてから）。
- `m[k]` でないキーを読むと実行時エラー（配列の範囲外と同じ扱い）。ないかもしれないときは `get` / `contains`。
  `m[k] = v` はないキーなら入れる（`m[k] += 1` は、ないキーならエラー）。
- `get` は値の写しを返すので、コピーできる値のときだけ。構造体の値は `m[k].x` と場所として読む。
- 中の値を `ref` で借りるのは禁止（リストと同じ。入れたり消したりで中の場所が変わる）。
- 一緒に `for (i, x) in a`（添字つき）も足した。辞書の `for (k, v) in m` と同じ形になる。
- 中身は今は「入れた順の並び＋キーから位置を引く表」。`remove` は後ろを詰めるので遅い（O(n)）。速さは IR / 実行時の設計でもう一度考える。

## モジュール（2026-10-23 に実装。書き方はカードの推奨 A で進めた）

- 1 ファイル = 1 モジュール。`use geom;` で同じフォルダの geom.jw を使う（Go のパッケージに近い）。
- **使う側はいつも `geom.area(p)` とモジュール名をつける。** 名前を見ればどこの定義か分かる（シャドーイング禁止・関数と同じ名前の変数の禁止と同じ考え）。
- **外に見せる定義には `pub`。** メソッド・フィールド・enum の種類は、型の `pub` に従う（細かい指定はあとで）。
- `use` の輪はエラー（読む順を決めるため。Go と同じ）。
- 作り: モジュールの中の定義の名前を `geom.area` に書き換えて（`modules.rs` の `qualify`）、全部を 1 つのプログラムにまとめる。
  なので型検査・解析・実行はモジュールを知らなくてよい。IR でもそのまま 1 つのプログラムとして扱える。

## 実行ファイル（`jabberwock build`。2026-10-23）

- `jabberwock build file.jw` で clang を呼んで実行ファイルを作る（`-O2`）。clang は利用者が入れる（Windows は llvm-mingw を勧める。docs/native.md）。
- **実行時エラーは、ふだんはインタプリタと同じ時系列の表示**（ソースの行つき）。そのためにソースを実行ファイルに入れる。
- **`--release` では使った位置だけ**（オーナーの指示）。ソースは入れない。
- 実行ファイルとインタプリタは、出力・エラー表示の全文・残った区画の数まで一致させる（`JW_NATIVE=1 cargo test`）。

## スレッド（2026-10-23。カードで案 A に決定）

- Go 風: `spawn(f)` と `chan<T>`。スレッドへ渡せるのは own とコピーできる値（中に ref のない「送れる型」）だけ。ref は型検査で弾く。
- 理由: own をムーブするだけなので、型検査だけでデータの取り合いが起きない。ロックもライフタイムも要らない。
- `join` は 1 回だけ。join しない task は捨てたところで待つ（スレッドが勝手に残らない）。
- スレッドの中のエラーはプログラム全体を止める（Go の panic と同じ）。全員が待ちならデッドロックのエラー。
- `scope` の中で ref を共有する案（B）と、ロックつきの共有（C）は、あとで足せる（docs/threads-design.md）。

## リストの要素を借りる（2026-10-24 に決定・実装。外部レビューの指摘 3 をオーナーが採用）

- レビューの指摘: 要素を借りるために `(own T)[]` にすると要素ごとにヒープを確保するので、構造体の配列のような書き方で遅くなる。
  案として「リストに世代を持たせ、長さが変わったら要素を借りた ref を無効にする」が挙がった。
- **リストの中身（要素の並び）を、own の先と同じく自分の区画に置く。** 要素を借りた ref は「中身の区画＋世代＋区画の中の道筋」を持つ。
  ref の形は今と同じ 32 バイトで、使うときの世代チェックも 1 回のまま。
- **要素が動くと世代を進めて、要素を借りた ref を無効にする**: 長さが変わる（push・pop・insert・remove・drain）・並びが変わる（sort・sort_by・reverse）。
  リストの解放・再代入・ほかのスレッドへ送るのも無効にする。エラーは「借りた → `push` でリストの要素が動いた → 使った」の時系列で出る。
  - 長さを変えること自体を止める案（借りている間は push できない）は、借りている数を数える仕組みが要るのでやめた。今の ref と同じ「使ったときに見つかる」にそろえた。
  - 領域を取り直したときだけ無効にする案は、無効になるかどうかが容量しだいになる（インタプリタと実行ファイルで結果が変わる）のでやめた。
- **リストをムーブしても、要素を借りた ref は有効**（中身の区画は動かないため。own の先を借りた ref と同じ）。要素への代入も有効なまま。
- 辞書は今までどおり値を借りられない（`remove` で後ろが詰まる。辞書の作りを見直すときに考える）。
- メソッドの receiver がリストの要素なら、ヒープへ貸すのをやめて、その要素を借りて `this` にした（IR・実行ファイルにも書き出せるようになった）。
- 作り:
  - インタプリタ: リストは `Value::List(スロット)`。中身 `Array(_, true)` をそのスロットに置き、要素の場所はそのスロットから数える（`list_place`）。
    要素が動いたら `list_moved` でスロットの世代を進める（中身はそのまま）。
  - 実行ファイル: リストの頭（要素の領域・長さ・容量）は今のまま。要素の領域の前に世代を置く（区画と同じ形）。
    要素を借りると世代に「借りられた」の印を立て、要素が動いたとき印があるときだけ世代を進める（push のたびに記録を書かずに済む）。
    一度も借りられていないリストは今までどおり realloc で伸ばし、free で返す。借りられたことがあれば、古い ref が世代を読めるよう、
    古い領域は区画として残す（OS に返さない）。ベンチマーク 8 本で、前と比べた差はぶれの範囲。
  - 検査を消す解析（IR）は、添字を通る ref を安全と見なさない（要素の ref はいつも実行時に検査する。配列の添字も、型を見ずに見分けられないので安全側）。

## ファイル・コマンド・終了（2026-10-24。自己ホストの準備）

- コンパイラを jabberwock で書くのに要るものとして足した（docs/self-hosting.md の A1〜A3）。
- `read_file` / `write_file` / `run_command` は失敗を `Result` で返す（`?` でつなげる）。エラーの文は OS の文を使わず、
  jabberwock で決めた短い文（`ファイルを読めません: パス` など）。interp と実行ファイルで同じ文になるように。
- `run_command(cmd, args)` はシェルを通さない（引数はそのまま渡る）。終了コードを返す。
- `exit(n)` は後片づけせずにすぐ終わる（C や Go と同じ）。型は「戻らない」。
- 値なしの値 `()` を足した。`Result<(), str>` を返す関数のため（`Ok(())`）。

## ビット演算・数の書き方・定数（2026-10-24。自己ホストの準備）

- ビット演算 `& | ^ << >> ~` は整数だけ。強さは Rust と同じ（比べるより強い。C の `x & 1 == 0` の落とし穴を避ける）。
- 型の幅以上ずらしたときは Go と同じく 0（`>>` の負の数は -1）。Rust のように止めず、C のように未定義にもしない。負の数だけずらすのは実行時エラー。
- `>>` は字句解析では `>` 2 つのまま（`Option<Option<i64>>` の型と区別するため）。式の中で `>` がすき間なく 2 つ並んだら `>>`。
- `const` は「使う場所に値を書いたのと同じ」にした（型を書かない）。数の型を使う場所に合わせられる。ファイルの中だけ（`pub` はこれから）。
- `0x` `0b` `0o` と `_` 区切り、エスケープ `\r` `\0` `\u{...}` を足した。
- 小数は `to_float()` と `to_bits()`（LLVM の小数の定数は 16 進のビットで書くため）。

## 値の中の return と join（2026-10-24。自己ホストの準備）

- 値として使う if / match の中でも `return` を書けるようにした（`let n = match t { case Some(x) -> x; default -> return Err(..); };`）。
  tinyc を書いて一番不便だったところ。`?` と同じく「関数をその場で抜ける」ので、評価途中の値は `?` と同じように解放する。
  外のループへの break / continue は今までどおり禁止（値がどこへ行くか分かりにくいため）。
- `str[]` の `join(sep)` を足した（Go の `strings.Join`）。

## エラーの文の言葉（2026-10-24。オーナーの指示）

- コンパイルエラー・実行時エラーの文は、**最終的には英語に統一する**。しばらくは慣れるため日本語のまま。
- 英語にするときは、interp・IR・実行ファイル（llvm.rs / jw_rt.c）の文を一字一句そろえたまま変える（突き合わせは全文を比べる）。jwc を書くときも同じ文を使う。

## 一時的な値を ref の引数に渡す（2026-10-24。自己ホストの準備）

- jwc の型検査を書いていて、`ty.is(ty.inner(t), "Own")` のように関数の結果を `ref` の引数へ渡せないのが一番の手間だった（いちいち `let` に入れる）。
- **`ref T`（mut でない）の引数には、場所でない式もそのまま渡せる。** 値は呼び出しのあいだだけ置いておき、呼び出しが終わったら（途中で `?` で抜けても）捨てる。
  Rust の「文の終わりまで生きる一時的な値」より短いが、ref を持ち出したら世代チェックで見つかるので安全は変わらない。
- `ref mut T` の引数は今までどおり呼ぶ側に `ref mut x` と書く（一時的な値を書き換えても見えないので、書けないままにした）。
- `[...]`・構造体や enum の値・数は、`ref T` の `T` を入れる先として型を決める（`count([1, 2])` がリストになるように）。

## 読むだけの写しの中の own は取り出せない（2026-10-24。安全性レビューから）

- `for s in ss` の s（構造体の要素）やクロージャに取り込んだ構造体は、中の own が「読むだけの写し」になっている。
  これを `let q = s.b;` と取り出すと、型は `own P` なのに中身は写しになり、実行ファイルでは
  (1) 解析が「own の型の変数には own が入っている」として検査を消し、解放後の区画を読み書きできた、
  (2) own の型なので spawn で別のスレッドへ送れた、(3) 書き換えが通った（interp はどれも正しくエラーか panic）。
- 決めたこと: **own（と own の配列）を場所から値として取り出すのは、中身が写しでも実行時エラー**（本物の own を取り出すときと同じ文）。
  型検査が `p.f` / `a[i]` / `*p` の型を見て `Expr.takes_own` を立て、interp はそれを値として読むとエラーにする。IR の exec は copy_out の行き先の型、
  実行ファイルは Hazard の手伝いの関数（own なら必ず真）で同じにする。借りる（`ref s.b`・`s.b.x`）のはよい。
- 型を `ref T` にする案もあったが、型検査には「値として使う場所」の決まった通り道がなく、`ref s.b` などの意味も変わるのでやめた。
  いままで写しを取り出せた書き方は、取り出してもムーブにならず「借りる」のと同じだったので、`ref` で書き直せば同じ動きになる。
- あわせて: 解析は copy_out の結果に Own の事実を付けない（念のため）。`jw_send_block` は写しのポインタ（下の 1 ビット）なら止める。
  interp の世代を u32 から u64 にした（同じスロットを 43 億回使い回すと、古い ref が有効に見えていた）。
- 確かめた取り出しの経路（tests/native.rs の `own_in_a_view_gives_the_same_error_on_every_path`。interp・実行ファイル・jwc で作った実行ファイルで同じ結果）:
  `let q = s.b`・`q = s.b`・添字 `ss2[0].b`・own の引数 `take(s.b)`・`return s.b` と最後の式・構造体のフィールド `T { p: s.b }`・
  enum の中身 `Some(s.b)`・`push(s.b)`・if の値・クロージャの戻り値・値の `match w.e`（enum の取り出しとして同じくエラー）・`*s`（構造体の取り出し）。
  通るのは借りる経路だけ: ref の引数 `look(s.b)`（自動で借りる）・`match ref w.e`・`ref s.b`・`s.b.x`。
  パターン分解 `let S { b } = s;` は文法にない（構文エラー）。`fn take` のメソッドは this が値なので、ref の s には呼べない（型エラー）。
- 将来の課題: これは型検査のエラーにしたい（今は実行時エラー）。own のフィールドは写しでなくても取り出せないので、
  「own（と own の配列）の型の `p.f` / `a[i]` / `*p` を値として使う」を型検査で弾けば同じ意味になる。値として使う場所の通り道を型検査に作るのが先。
  **優先度は高め**: ジェネリックな関数の中の `T` の穴（下）も、型の引数ごとに調べる（または `T` を値として取り出す場所を記録する）ことで実行前に見つけられる。
  公開する前に、少なくとも解析で分かる場所は警告にしたい。
- for の中で回しているリストを pop・push してよいかは、今のまま「よい」とする（禁止しない）。for は始めた時点の要素を回し、
  コピーできる値はその写し、own と構造体の中の own は世代つきで借りているので、取り除かれた要素の own をたどると実行時エラーになる（spec の 8.9）。
  イテレータ自体に世代を持たせる必要はない（要素ごとに守られている）。
- 写しのポインタ（下の 1 ビット）が本物と混ざる経路の確認: own と ref の比較（`==`）は型検査が禁止、辞書のキーは数・文字列・bool だけ、
  ポインタを文字にする方法はない。表示・interface の呼び出し・クロージャへの取り込み・解放はどれも下の 1 ビットを見て写しの先をたどる（interp と同じ表示を確かめた）。
  ほかのスレッドへ送るのは `jw_send_block` が止める。
- スレッドを作れなかったとき（pthread_create / CreateThread / `std::thread::Builder::spawn` の失敗）は、前は何も知らせずに
  join が永久に待っていた（生きているスレッドの数に入ったまま）。**spawn の位置で実行時エラー「スレッドを作れませんでした」にした**（interp と jw_rt.c で同じ文）。
  生きているスレッドの数は、作れたあとで足す（錠を持ったまま作るので、新しいスレッドが先に終わって数を減らすことはない）。
  送るはずだった値: interp は捨てる（own のスロットは送ったときに空けてある）。実行ファイルはエラーでそのまま終わるので、ほかの実行時エラーと同じく片づけない
  （二重解放にはならない）。失敗はふつう起こせないので、環境変数 `JW_MAX_THREADS` で上限を下げて起こし、テストする（`spawn_fails_with_an_error_when_no_thread_can_be_made`）。
  `--release` の実行ファイルはこの環境変数を見ない（テスト用の仕組みを本番に残さない）。
- 2 回目の確認（別の発想で。tests/native.rs の `own_in_a_view_through_generics_and_builtins`）で、**型の引数を通る穴**が見つかった:
  `fn T get<T>(ref Box<T> b) { b.v }` に写しの `Box<own P>` を渡すと、関数の中の `b.v` の型は `T` なので型検査が `takes_own` を立てられず、
  interp だけ写しを取り出せた（実行ファイルと IR は型の引数ごとに作り分けるので、もともとエラー）。interp は型を見ないので、
  写しの ref に印 `RefVal.view` を付け（`view_of` が作るときだけ。`ref s.b` で借り直すと消える）、値として取り出すときに値の中に印があればエラーにした。
  `Box<ref P>` に本物の ref を入れたものは今まで通り取り出せる。
- 組み込みの操作は、取り出す操作（pop・remove・drain・sort・辞書の remove）はどれも書き換えなので、読むだけの写しには型検査がエラーにする。
  `filter` と辞書の `get` はコピーできない要素には使えない。`map` の要素と `for (k, v) in m` の v は ref なので、取り出しにならない。
- interp と実行ファイルの差分を自動で探す（tests/fuzz.rs）: 種から小さなプログラムを作り（写しの印の表の部品: for の要素・クロージャの取り込み・
  `Box<T>`・match ref・for / map・リストの pop / push / sort_by と、取り出す・借りる・読む文）、interp と実行ファイルで出力とエラーを全文比べる
  （デバッグビルドなら IR も）。取り出す文は 8 回に 1 回にして、最初の文で止まるものばかりにならないようにした。
  ふだんの `cargo test` は 40 本。`JW_FUZZ=本数`・`JW_FUZZ_SEED=始めの種`、`JW_FUZZ_JWC=jwc の実行ファイル` で jwc で作った実行ファイルとも比べる。
  2026-10-24 の時点で、2000 本（interp・IR・実行ファイル）と 300 本（jwc も）でずれなし。型の引数の穴と、印が残りすぎる穴を戻すと、
  どちらも 200 本以内で見つかった。
- 差分テストの部品を足した（A-4・A-6）: main の始めにリストの要素を借りた ref（`ref ss[0]`・`ref ss[1].b`・`ref ss[0].n`・メソッドが返す ref）を置き、
  要素が動く操作（pop・push・insert・remove・reverse・sort_by・要素への代入）のあとで使う。メソッドの this は場所・一時的な値（`mk(1).first()`）・`fn take`。
  辞書の値のメソッドは、まだ実行ファイルに書き出せないので部品に入れていない。**この経路（辞書の値をヒープへ貸して借り、戻す）は実行ファイルでは未検証**
  （interp と IR の突き合わせは tests/methods.rs などで通る）。実行ファイルに書き出せるようにしたら、部品（`m["a"].first()`・`m["a"].bump()`・`m["a"].nref()`）に足すこと。
  これで 1 つずれが見つかった: 一時的な構造体の this を捨てたとき、interp だけ中の own の解放の理由が「持ち主が解放されたので、中身も連鎖して解放された」
  になっていた（貸すためのスロットごと解放していたため）。実行ファイルと同じく「メソッドの呼び出しに使い終わった一時的な値」にそろえた
  （安全性は同じで、エラーの文だけの違い。IR との突き合わせはエラーの題と位置しか比べないので気づかなかった）。直したあと 3000 本（interp・IR・実行ファイル）と 300 本（jwc も）でずれなし。
- **運用**: 新しい取り出し経路や組み込みの操作を足したら、tests/fuzz.rs の部品にも足す。`let S { b } = s;` のような分解を文法に足すときも、
  先に経路の表（上）と部品に足してから入れる。大きな変更のあとやリリースの前は、`JW_FUZZ=10000` 以上で一度回す（1 万本でおよそ 20 分）。
- 写しの印（`RefVal.view`）の一覧（3 回目の確認。tests/native.rs の `view_mark_is_kept_or_dropped_where_it_should_be`）:
  付くのは `view_of` が own を ref にするときだけ（for の構造体の要素の中・クロージャの取り込み）。写しの写しは印を引き継ぐ。
  消えるのは ref の型の名前で受け取るとき: `ref s.b` と自動で借りる引数（`make_ref`）・メソッドの this・`match ref` で受けた中身・
  写しのリストを回す `for p in s.ps` / `for (k, v) in x.m`・`map` と `sort_by` の要素（`unview`）。
  最初は `match ref`・for・map・sort_by で印が残っていて、ジェネリックな関数に渡すと正しい書き方がエラーになっていた（実行ファイルは通る）ので直した。
  own の型の場所（写しの構造体のフィールド・写しの配列の要素・クロージャに取り込んだ変数）では残り、取り出すとエラー。
  interface: `ref Shape` として借りる・渡すのはよく、`own Shape` へ取り出す（じかに、またはジェネリックな関数を通して）のはエラー。
  表の行ごとのテスト（`u_` は印が消えて `Box<ref P>` などの正しい書き方が通るもの、`k_` / `g_` は印が残ってエラーになるもの）:

## 数のメソッド sqrt・abs・max・min（2026-10-25。ベンチマークの n-body のため。オーナーの了承）

- 関数（`sqrt(x)`）でなくメソッド（`x.sqrt()`）にした。`to_bits` と同じ形で、組み込み関数の名前が利用者の関数名とぶつからない。
- 整数にも `abs` / `max` / `min` を足した（オーナーの提案）。`max` / `min` の引数は receiver と同じ型にそろえる（`expect`）。型の違う整数どうしは比べない。
- 整数の `abs` は一周させる（`i64` の最小の値はそのまま）。整数のあふれはどこでも一周させる決まりに合わせた。実行時エラーにはしない。
- 小数の `max` / `min` は LLVM の `maxnum` / `minnum` と Rust の `f64::max` に合わせて、`NaN` でないほうを返す。`-0.0` と `0.0` のどちらを返すかは決めない（環境で変わりうる）。
- 書き出し: IR は `Rvalue::Builtin("f64.sqrt" / "int.max" など)`。LLVM は小数が intrinsic（`llvm.sqrt.f64` など）、整数は比べて select（intrinsic の宣言を幅ごとに増やさないため）。


## 並べ替えの手順と sort_unstable（2026-10-25。ベンチマークでマージソートが Rust の 2〜5 倍遅かったため。オーナーの了承）

- オーナーの選んだ形: `sort` / `sort_by` は安定のまま手順を変え、安定でない `sort_unstable` / `sort_unstable_by` を足す（Rust と同じ名前・同じ分け方）。
- 調べて分かったこと: 実行ファイルでは比べる関数（`sort_by` の関数も、`sort()` の組み込みの比べ方も）を実行時ライブラリから関数ポインタで呼ぶので、
  かかる時間はほぼ「比べる回数」で決まる（1 回 6〜7 ナノ秒。呼び出しと、結果で分かれる分岐の読み違い）。Rust が速いのは比べ方をその場に埋め込めるため。
  最初に試した安定なクイックソート（run の検出つき）は、C で比べ方を埋め込んだ試作では速かったが、関数ポインタで呼ぶと比べる回数が 2 割多いぶん
  ばらばらな 300 万個で 0.43 → 0.56 秒と遅くなったのでやめた。
- 安定（`sort` / `sort_by`）: 並んだ部分（run。真に減っていれば逆にする）を見つけ、min_run（32〜64、Timsort と同じ決め方）より短ければ
  二分挿入ソートで伸ばし、run どうしは powersort の決まりで合わせる（Timsort / Python の sort の仲間。比べる回数が少ない手順）。
  ばらばら 0.43 → 0.36 秒（関数ポインタで比べたとき）、並んだもの・逆に並んだものは n 回の比べで終わる。
- 安定でない（`sort_unstable` / `sort_unstable_by`）: 全体が 1 つの run ならそのまま（降順なら逆に）。ほかは pdqsort に近いクイックソート
  （その場で 2 つに分ける。深さが 2 log2 n を超えたらヒープソート）。作業用の場所がいらないのが利点。関数ポインタで比べると比べる回数が多いぶん
  `sort_by` より少し遅いことがある（spec にも書いた）。
  pivot は 9 個の中央値の中央値。場所を n/8 の倍数にしたら周期のある並び（のこぎり形）と重なって 2 乗の時間になったので、
  n から決まる疑似乱数（splitmix の混ぜ方）の場所にした。乱数の種を毎回変えないのは、比べる回数と順番を決まったものにするため。
  前の pivot と同じ値の pivot を選んだら、等しい要素をまとめて片づける（pdqsort の工夫。同じ値が多い並びで速い）。20 個以下は挿入ソート。
- **整数の `sort()` / `sort_unstable()` は、実行ファイルでは比べる関数を使わない基数ソート**（jw_rt.c の `jw_sort_int`）。
  比べ方が組み込みなので呼ばれ方は見えず、同じ値の整数は見分けがつかないので、結果は比べて並べたものと必ず同じ。
  並んでいれば（逆も）そのまま、64 個以下は挿入ソート、ほかは最小の値を引いて要る桁だけ 11 ビットずつ（i64 の 300 万個で 3 回）。
  8 バイトの整数は元の場所を鍵に使うので、作業用の場所は n 個ぶん（マージソートと同じ）。interp は src/sort.rs の手順のまま（結果は同じ）。
  小数と文字列は今は比べる関数で並べる（-0.0 と 0.0・NaN の扱いがあるので、基数ソートにするなら別に決める）。
- **interp（`src/sort.rs`）と実行時ライブラリ（jw_rt.c）は、比べる関数を使う手順では同じ順に比べる**。`sort_by` の関数は print や
  取り込んだ `ref mut` で呼ばれ方が見えるので、比べる回数と順番も interp と実行ファイルで突き合わせる（tests/native.rs の `sorting_matches_interp`）。
- 比べる関数が矛盾しても、範囲の外を読まず必ず終わるように、どの走査も範囲で止める（挿入ソート・分割・run の検出）。
- ついでに見つけた不具合: 仕様どおりクロージャに取り込んだ `ref mut r` で `*r = ...` と書くとエラーになっていた（types の `access` が
  取り込んだ変数そのものの書き換えと区別していなかった）。取り込んだ ref の先の書き換えは許した（取り込んだ own の `*o = ...` はエラーのまま）。

## リストの要素を借りた ref の検査を消す（2026-10-25。ベンチマークの refmut で 9.7 億回の世代の検査が残っていたため。オーナーの了承）

- `let p = ref mut ps[i]` の p は、ps の要素が動く操作までは必ず生きている。IR の解析に事実 `RefElem(x)` を足した:
  「変数 x（Pinned の引数・own の持ち主・リストの変数）から届くリストの要素を指す」。この事実のある ref の最初の Deref は検査を消す。
- 消える場面（`kill_elems`）: リストの操作（len・contains・get・keys 以外）・関数の呼び出し（関数の値・interface の呼び出しも）・
  組み込みの操作（数・文字列の計算と print・連結・assert 以外）・リストを持ちうる値の代入・リストを持ちうる型の drop / discard。
  どこかのリストの要素が動くかもしれない操作で、どの RefElem もまとめて消す（どのリストかは見ない。安全側）。
- RefElem の ref は「生きている」とは見なさない（呼び出しの引数として Pinned の根拠にはしない）。呼ばれた先でリストが変わりうるため。
- 結果: refmut の世代の検査 9.7 億回 → 0、0.30 秒 → 0.28 秒（残りは借りた印の書き込みと、ポインタが重なりうることによる読み直し）。
  n-body の検査もすべて消えた。

  - 値は 64 ビットの札（世代 << 21 | 番号 << 1 | 写しの印）。表は塊ごとに確保して動かさない。確保と解放だけ g_lock で守る（送れないので、中身に触るのは持ち主のスレッドだけ）。
    世代の上限では退役（ref の区画と同じ）。札を確かめる検査は、型検査で防げているはずのことの念のための検査。
  - 設計にある Busy 状態・所有スレッドの実行時検査・解放結果の 4 区分（Released など）・資源数の設定は、送れない・同期だけの今の範囲では後回し。
    close が失敗しても場所は空ける（fclose は失敗しても FILE を手放すため）。
  - 失敗の経路は環境変数 `JW_RES_FAIL` でわざと失敗させて確かめる（`JW_MAX_THREADS` と同じく、--release では効かない）。
  - 外部の副作用を持つが、jwc にはインタプリタとの自動照合がないので、照合の抑止はまだ要らない（Rust 版は対応しない）。
- std.fs のディレクトリ操作と std.net の TCP（2026-10-30、オーナーの了承のうえ）: ディレクトリは資源にせず関数だけ（開いたままにしないので）。
  list_dir は名前の順に並べる（OS の返す順は決まっていないので、出力を同じにするため）。TCP は TcpStream・TcpListener を資源に足し、表は File と共用（種類で閉じ方を分ける）。
  Windows の std.net は Winsock の初期化を含めて後で足す（今は Err を返すだけ。ここでは Windows のビルドも実行も確かめていない）。
  SIGPIPE で止まらないよう、送るときは MSG_NOSIGNAL（macOS は SO_NOSIGPIPE）を使う。
- std.http（2026-10-30、オーナーの了承のうえ）: 設計では HTTP は初期版の外だったが、オーナーの希望で std.net の上に .jw だけで最小のクライアントを置いた（コンパイラ・実行時ライブラリは変えない）。

- std.env・std.time・std.json（2026-10-30、オーナーの判断で入れた。軽量ブラウザの試作で要るため）: env と time は実行時ライブラリの小さな組み込み
  （`__env_get` / `__time_now_ns` / `__time_sleep_ms`。それぞれ std.env・std.time の中だけで呼べる）。time は設計の std.time のうち単調時計と待機だけで、Duration・Deadline はまだ。
  json は .jw だけ。借りて match したときに中を読めるよう、Arr と Obj の中身は own にした（own でない list は借りた match で受け取れないため）。

- Windows の std.net（2026-10-30、オーナーの指示）: Winsock を使う。ws2_32.dll は初めて使うときに LoadLibraryW で読み込み、関数は GetProcAddress で取る。
  リンクの指定（-lws2_32）を増やさないため（Rust 版で作る実行ファイルも同じ実行時ライブラリを使い、Rust 版は凍結なので）。windows.h は今までどおり入れない。

  確かめたのは Linux の上の mingw（クロスコンパイル）と wine で、本物の Windows ではまだ（std.net・std.http のテストのプログラムが Linux と同じ出力）。
- std.tls と https（2026-10-30、オーナーの選択「Windows と Linux」）: 設計では Linux の TLS は Unsupported だったが、オーナーの選択で Linux も入れた。
  外部のクレートも -l の指定も増やさないため、どちらも OS の部品を初めて使うときに読み込む（Linux は dlopen で OpenSSL 3 の libssl、Windows は LoadLibraryW で Schannel と crypt32）。
  ない環境では connect が Err になるだけで、TLS を使わないプログラムには関係しない。証明書の確かめは必ずする（やめる指定は作らない）。取り消しは調べない。
  Windows は Schannel の自動の確かめ（SCH_CRED_AUTO_CRED_VALIDATION）を使わず、握手のあとに crypt32 で鎖と名前を確かめる。wine では自動の確かめが何もしなかったため
  （鎖の途切れも、SSL の決まりの結果に加えて鎖の状態で見る）。終わりの知らせは中身のない OK で返る実装（wine）もあるので、記録の種類（21）でも見分ける。
  TLS 1.3 は Windows では使わない（Schannel の 1.3 は版によって動きが違うため。Linux は 1.2 以上で OpenSSL に任せる）。
  確かめたのは Linux（OpenSSL 3）と、mingw で作って wine で動かした Windows 版で、本物の Windows ではまだ。テストは Linux だけ（tests/tls の試験用の証明書で openssl s_server を立てる）。
